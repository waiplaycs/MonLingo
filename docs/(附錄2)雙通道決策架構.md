**版本:** 1.0
**日期:** 2025年9月16日
**狀態:** 提案

## 1.0 核心理念：應對數據不確定性的智能決策

在版面分析中，並非所有內容都擁有足夠的統計樣本來支持複雜的算法模型。例如，一個僅有數行的文本塊，無法有效形成「雙峰分佈」。強行使用統計模型處理這類「低可信度」數據，結果往往不可靠。

為解決此問題，我們引入了 **「雙通道決策架構 (Dual-Channel Decision Architecture)」**。

### 類比：智能導航系統

> 想像一個智能導航 App，它會根據路況和距離選擇最佳交通方式：
> - **路況清晰、距離遠 (高可信度):** 系統會推薦你走**高速公路**，因為它效率最高、路徑最優。這對應我們的**「雙峰統計通道」**。
> - **路況複雜、距離短 (低可信度):** 系統會推薦你走**市區普通道路**，依賴紅綠燈、路牌和經驗規則來導航。這對應我們的**「經驗規則通道」**。

此架構的核心是在分析之初，首先評估數據質量，然後智能地選擇最合適的分析「通道」，確保算法在任何情況下都能做出穩健、合理的決策。

## 2.0 通道選擇器 (Channel Selector)

「通道選擇器」是架構的大腦，它在對一個欄位 (Column) 進行段落分割前，會進行快速的預檢查，以決定進入哪個分析通道。

### 2.1 觸發「經驗規則通道」的條件

當以下**任一條件**被滿足時，系統將判定當前數據為「低可信度」，並切換到「經驗規則通道」：

1.  **樣本數量不足:**
    - **條件:** `總間距數量 < 8` (經驗值，可調)
    - **原因:** 統計樣本過少，無法形成有意義的分佈。

2.  **峰值模式不明顯:**
    - **條件:** `有效峰值數量 < 2`
    - **原因:** 無法找到「段落內」和「段落間」兩種清晰的間距模式。

3.  **峰值區分度低:**
    - **條件:** `peak_split / peak_merge ≤ 1.5`
    - **原因:** 兩個峰值距離太近，統計上無法有效區分，強行使用會導致決策模糊。

### 2.2 觸發「雙峰統計通道」的條件

如果**不滿足**上述任何一個「經驗規則通道」的觸發條件，系統將默認進入常規的**「雙峰統計通道」**，利用其強大的統計分析能力處理數據。

## 3.0 「經驗規則通道」的分析策略

### 🤔 引言：何時需要經驗規則通道？

當雙峰統計模型因為數據不足或模式模糊而失效時，「經驗規則通道」將被激活。這通常發生在以下幾種特徵的欄位中：

1.  **結構高度一致的內容 (Highly Structured & Uniform Content):**
    - **特徵:** 行間距高度統一，只有一個統計峰值。
    - **案例:** 列表、UI選單、代碼塊、表格。

2.  **內容極簡的欄位 (Minimalist Content Columns):**
    - **特徵:** 行數太少（例如少於8行），無法提供足夠的統計樣本。
    - **案例:** 標題、圖片說明、簡短提示。

3.  **間距模式模糊的內容 (Ambiguous Spacing Patterns):**
    - **特徵:** 段內和段間距非常接近，無法清晰分離出兩個峰值。
    - **案例:** 高密度排版（如法律文件）、格式混亂的文本。

當數據被判定為「低可信度」時，系統不再依賴行距的統計分佈，而是轉向分析更穩定、更具體的局部特徵。它會像一個經驗豐富的排版師，通過觀察以下線索來計算「合併分數」。

【評分總則｜以合併為目標的加減分】
- **分數起點:** 從 `0` 開始累積，允許「加分與扣分」。
- **訊號處理:** 支援合併的線索→加分；不利合併（暗示分割）的線索→扣分；若遇到強分割線索→採用「硬性分割」直接終止合併判定。
- **合併判定:** 當最終合併分數達到或超過「合併閾值」即判定合併；未達則分割。
- **閾值約定:** 預設合併閾值 `T_merge = 3.0`，可依欄位/文檔特徵動態調整。

### 3.1 策略一：基於字體層次的扣分 (Font Hierarchy)

- **類比:** 通過制服大小和樣式識別職位層級。
- **規則:** 比較相鄰兩行的字體大小和樣式。
- **評分機制（扣分項）:**
    - **無扣分 (0分):** 字體大小相對差異 ≤ 5% 且樣式一致。
    - **輕度扣分 (-1.0分):** 字體大小相對差異在 5% - 15% 之間，或存在輕微樣式差異。
    - **重度扣分 (-2.0分):** 字體大小相對差異 ≥ 15% 或樣式顯著變化（如由常規體切換為粗體/斜體/標題字）。

### 3.2 策略二：基於對齊模式的扣分 (Alignment Patterns)

- **類比:** 觀察隊伍的排列規律，識別是否有人換列或縮進。
- **規則:** 檢測相鄰兩行是否存在顯著的縮排變化或對齊方式切換。
- **評分機制（扣分項）:**
    - **無扣分 (0分):** 左邊界 X 差異小於一個字符寬度，且對齊方式一致。
    - **輕度扣分 (-1.0分):** 輕微邊界抖動但仍屬同一對齊風格。
    - **重度扣分 (-2.0分):** 出現新的縮排、懸掛縮排，或對齊方式切換（左→中/右）。

### 3.3 策略三：基於內容語義的合併評分 (Semantic Cues)

- **類比:** 通過對話的開頭詞（如「另外...」）判斷話題切換。
- **規則:** 檢測一行的開頭是否包含列表標識符或結構性關鍵詞。
- **評分機制（合併視角）:**
    - **硬性規則（直接分割）:** 若行首為列表標識符（`1.`, `a)`, `*`, `-`, `•`, `■` 等），視為新段落起始，直接在此分割；本策略不加分，並可跳過其餘合併評分。

### 3.4 策略四：基於統計自適應的合併評分 (Statistical Adaptive Spacing)

- **類比:** 智能溫控系統不使用固定的「18°C」，而是根據歷史溫度數據動態計算「過冷」和「過熱」的閾值。
- **規則:** 由於進入經驗規則通道的前提是樣本量不足（< 8個間距），此策略專門應對這種數據稀少的情況。它放棄固定的乘數或像素值，利用統計特徵（平均值與標準差）建立自適應判斷基準，並輸出「合併分數」。

#### 核心挑戰：樣本量不足的統計難題

在經驗規則通道中，我們面臨的核心挑戰是：**如何在樣本極少的情況下，仍然做出基於統計的合理判斷？**

- **欄位級統計的困境:** 當一個欄位只有3-7個間距時，單憑這幾個數值計算出的平均值和標準差往往不穩定，容易被極端值扭曲。
- **全局級統計的優勢:** 基於整個文檔的統計數據更加穩定可靠，能為小樣本欄位提供一個堅實的判斷基準。

#### 推薦方案：全局級統計 (Document-Level Statistics)

- **核心思想:** 當欄位內樣本量不足以支撐可靠的局部統計時，借用整個文檔的「排版DNA」作為判斷基準。
- **計算方式:**
    1.  **首次觸發時**，計算 **整個文檔** 所有行距的 `全局平均值 (global_mean)` 和 `全局標準差 (global_stdDev)` 並緩存。
    2.  使用全局數據定義閾值：
        - `split_threshold = global_mean + global_stdDev * 1.0`
        - `merge_threshold = global_mean - global_stdDev * 0.5`
- **評分機制（合併視角）:**
    - **合併加分 (+1.0分):** `當前行距 < merge_threshold`（間距顯著偏小，支援合併）。
    - **無加分 (+0分):** `merge_threshold ≤ 當前行距 ≤ split_threshold`（屬於模糊區間）。
    - **硬性規則（直接分割）:** `當前行距 > split_threshold` 視為段間距，直接在此分割；本策略不加分，並可跳過其餘合併評分。
- **優勢:** 在樣本量不足的約束下，提供最穩定可靠的統計基準，避免因局部數據稀少而導致的決策偏差。

 

### 3.5 最終決策

- **計算:** 從 `0` 開始累積各策略的「帶符號分值」（可正可負；策略三未觸發時視為 `0`，若觸發則直接分割並跳過加總）：`最終合併分數 = 策略一分值 + 策略二分值 + 策略三分值 + 策略四分值`。
- **合併閾值:** 設定 `T_merge = 3.0`（可調整）。
- **決策:**
    - 若 `最終合併分數 ≥ T_merge` → 將兩行**合併**到同一段落。
    - 若 `最終合併分數 < T_merge` 或遇到「硬性分割」條件 → 在此處**分割**，創建新段落。

    > **關於動態閾值:** 可將固定的 `T_merge` 動態化，依欄位特徵（如平均行數、字體變化頻率、內容類型）自適應調整，以避免過度合併或過度分割。

## 4.0 架構優勢

1.  **智能適應 (Intelligent Adaptation):** 根據數據質量自動選擇最合適的分析模型，兼顧準確性與效率。
2.  **穩健性提升 (Enhanced Robustness):** 徹底避免了在樣本不足時濫用統計模型導致的錯誤決策，顯著提升了算法在邊緣情況下的穩定性。
3.  **互補覆蓋 (Complementary Coverage):** 統計通道處理複雜、長篇的連續文本，經驗通道則精準處理短小的、結構化的內容（如列表、標題、UI元素），兩者形成完美互補。
4.  **高度可解釋性 (High Interpretability):** 「經驗規則通道」的決策邏輯清晰直觀，極大地方便了算法的調試、分析和後續優化。
