## A.概念重覆
### 1. 專案/模組結構重覆
5.1「專案結構組織」與 11.1「專案結構完整對應」內容大幅重疊。
建議：保留 11.1 為正式規格，5.1 刪除或簡化為「專案結構概述」。

### 2. NativeBridge 介面定義重覆且版本不一
2.2.5 與 5.2.1 都定義了 NativeBridge，簽名與命名略有差異（見下方「衝突」）。
建議：集中於一處（建議 2.2.5），其餘位置只連結參照。

### 3. UI/視覺樣式與控制項實作範例重覆
11.2 大量 XAML/樣式與先前 UI 架構描述重疊。
建議：11.2 保留為「UI 實作範例」，其餘章節僅保留概述或連結。

### 4. 核心流程描述重覆
3.1 與 10.x、11.x 均詳述 OCR/擷取/顯示流程，細節重複。
建議：保留 11.x 為權威 OCR/擷取/顯示流程，其餘章節僅作簡短概述或連結。

## B.概念衝突
### 1. OCR 引擎不一致
2.3.2 明確為 PaddleOCR；4.1 表格寫「Tesseract 引擎整合」；8.1 對比表也寫「Tesseract + k-means」。
建議：統一為 PaddleOCR（已在 Native 層與依賴表與流程全面鋪陳），4.1/8.1 改為 PaddleOCR + k-means。

### 2. 平台目標不一致
2.1 寫 AnyCPU；6.2 要求 x64；且原生 DLL 與 OpenSSL/DirectX 均為 x64。
建議：統一為 x64（Exe/Native/所有 NuGet 依賴），移除 AnyCPU。

### 3. 設定存儲方案不一致
2.2.3 的 ConfigService 用 JSON（AppData/config.json）；5.3.1 改用 ManagedMmkv；4.3.1 表格也宣稱用 ManagedMmkv。
建議：依你定義的「Part 10/11 為最高標準」，統一採用 %AppData%/MonLingo/config.json。將 5.3.1 的 ManagedMmkv 移至「替代方案/附錄」，並把 4.3.1 表格改回 JSON。若未來改採 MMKV，需同步更新第 10/11 節。

### 4. SQLite 實作與套件不一致
依賴清單列 SQLitePCLRaw；5.3.2 的程式碼風格較像 Microsoft.Data.Sqlite。
建議：選 SQLitePCLRaw 為標準（既已列於依賴），替換程式碼片段與命名以一致。

### 5. 熱鍵技術路徑不一致
2.3.3 主張 SetWindowsHookEx（低階掛鉤）；3.1.1/熱鍵細節使用 RegisterHotKey + WM_HOTKEY。
建議：熱鍵採 3.1.1 的路徑 RegisterHotKey（更輕量且足夠），保留滑鼠/全域掛鉤僅在必要功能（如選區拖曳跨視窗）使用。

### 6. Native API 簽名/命名不一致
2.2.5 的 screenshot_window_loop_read(byte[] buffer, ref int size)；5.2.1 另有 (ref int size, ref int width, ref int height)。
2.2.5 的 ocr_run_pipeline(byte[] imageData, int size)；5.2.1 另有 (byte[] imageData, int size, int width, int height)。
視窗 API 命名有 GetWindowUnderCursor vs get_window_under_cursor 的落差；部分函式（如 ocr_get_line_bounding_box、ocr_get_line_word_count）在使用處有出現，但 2.2.5 未列出簽名。
建議：以 2.2.5 為單一權威清單，補齊所有被使用到的 API 簽名；若實作確需 width/height，更新 2.2.5 並全書一致。對不同導出名稱使用 DllImport 的 EntryPoint 映射以統一 C# 命名。

### 7. get_sign_str 型別用法不一致
Native 定義回傳 IntPtr；3.1.1 範例程式直接以 string 接收。
建議：維持 Native 回傳 IntPtr；C# 端一律透過 NativeBridge.MarshalAndFreeString 轉字串並釋放，並修正 3.1.1 範例中以 string 直接接收的寫法。

### 8. OCR API 名稱拼字不一致
文中同時出現 ocr_destory 與 ocr_destroy。
建議：統一 ocr_destroy，校對全文。

### 9. 依賴與授權資訊不準確
OpenSSL 1.1 的授權非 Apache-2.0（OpenSSL 3 才改 Apache-2.0；1.1 是 OpenSSL License/SSLeay）。
Prism 授權為 MIT，表格寫「Prism License」不準確；NAudio 授權為 MIT。
建議：更正授權欄，避免法務風險。

### 10. UI 命名空間不一致
前文使用 MonLingo.Interface.*（表現層）；後文與結構圖使用 MonLingo.View / MonLingo.ViewModel。
建議：統一使用 View / ViewModel 命名，移除 Interface.*。

### 11. FPS/消費頻率與敘述落差
宣稱 60+ FPS 擷取；3.1.4 消費端用 DispatcherTimer 100ms（10 FPS）。
建議：明確策略為「生產者高頻、消費者讀取最新幀以降負載」，或改事件驅動/提高 Timer 頻率；同步更新性能描述。

### 12. 小問題/編輯異常
2.2.5 使用 Rectangle（System.Drawing）而 WPF 多用 Rect（System.Windows）；建議統一資料型別並說明座標系轉換。


## C. 建議的統一決策（優先級）
### 0. 保留 11.x 為權威 OCR/擷取/顯示流程，其餘章節僅作簡短概述或連結。
### 1. OCR 引擎：統一 PaddleOCR + k-means。更新 4.1/8.1/表格敘述與所有示例。
### 2. 平台：統一 x64，移除 AnyCPU；在 PRD 明寫「MonLingo.exe PlatformTarget = x64」。
### 3. 設定存儲：統一 config.json（%AppData%/MonLingo/config.json）；將 5.3.1 的 MMKV 移至附錄或標註為替代方案。
### 4. SQLite：統一 SQLitePCLRaw；修正文中的程式碼與命名。
### 5. 熱鍵：預設 RegisterHotKey；僅在需要時才使用 SetWindowsHookEx（滑鼠/特殊場景）。
### 6. NativeBridge：以 2.2.5 為權威，補齊缺漏 API，統一函式簽名/命名（必要時用 EntryPoint 對應）。
### 7. 安全字串：採用 IntPtr → NativeBridge.MarshalAndFreeString 的模式，統一轉字串與釋放，並修正 3.1.1 範例。
### 8. 授權欄：修正 OpenSSL/Prism 等授權標示。
### 9. 命名空間：統一 MonLingo.View / MonLingo.ViewModel；移除 Interface.*。
### 10. 效能敘述：明確「擷取 60FPS、消費端讀最新幀」，或提高消費頻率/改事件驅動。
### 11. 小問題：統一 Rectangle/Rect，說明座標系轉換。
