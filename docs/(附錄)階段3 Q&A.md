## Q1: v3.1雙峰自適應閾值計算規則

**問題:** `v3.1雙峰自適應閾值：2.44 (動態基礎2.00 + 雙峰調整0.44)` 中的 2.00、0.44 這些數字是怎麼得出的？每項的評分標準是什麼？

**答案:**

### 動態基礎分 (2.00)
- **計算規則:** 基於 `peak_merge` 動態計算的基準合併閾值
- **計算公式:** `Math.Min(2.0, Math.Max(1.0, peak_merge * 1.2))`
- **設計理念:** 根據文檔的實際間距特徵調整基礎閾值，避免小間距文檔閾值過高的問題
- **適用場景:** 適用於所有欄位，根據雙峰模型的合併峰值動態調整

### 雙峰調整分 (0.44)
包含兩個子項目的綜合調整：

#### 1. 峰值分離度調整
- **計算公式:** `Math.Min((peak_split - peak_merge) / peak_merge, 1.0) * 0.3`
- **計算邏輯:** 當雙峰差距越大時，說明該欄位的「段落內」和「段落間」特徵越分明，因此可以適當提高合併閾值，要求更嚴格的合併條件
- **權重限制:** 調整因子最大為 0.3，避免過度調整

#### 2. 峰值可信度調整
- **高可信度情況:** 當有效峰值 ≥ 2 且總間距 ≥ 3 時，調整 -0.3（更激進的合併）
- **低可信度情況:** 當峰值數量不足或間距太少時，調整 +0.2（更保守的策略）
- **設計理念:** 根據雙峰模型的統計可靠性調整合併策略

### 最終閾值計算
`最終閾值 = 動態基礎 + 峰值分離度調整 + 峰值可信度調整`

**示例計算:**
```
假設: peak_merge = 5px, peak_split = 15px, 有效峰值 = 2, 總間距 = 5

動態基礎 = Min(2.0, Max(1.0, 5 * 1.2)) = 2.0
分離度調整 = Min((15-5)/5, 1.0) * 0.3 = Min(2.0, 1.0) * 0.3 = 0.3
可信度調整 = -0.3 (高可信度)

最終閾值 = 2.0 + 0.3 + (-0.3) = 2.0
```

## Q2: 強合併信號得分計算規則

**問題:** `合併區間：間距1.0px → 合併閾值2.4px → 強合併信號(4.50分)` 中的 4.50 分是怎麼計算出來的？

**答案:**

### 計算公式 (v3.4 雙峰區間簡化版)
```pseudocode
function CalculateDistanceScore(current_spacing, peak_merge, peak_split, tolerance):
    // 假設: current_spacing = 1.0px, peak_merge = 2.4px, peak_split = 15px, tolerance = 0.48px
    
    // 計算區間邊界
    double merge_boundary = peak_merge + tolerance; // 2.4 + 0.48 = 2.88px
    double split_boundary = peak_split - tolerance; // 15 - 0.48 = 14.52px
    
    // 1. 檢查分割區間
    if current_spacing >= split_boundary: // 1.0 >= 14.52? ✗
        return -10.0; // 強制分割
    
    // 2. 檢查合併區間  
    if current_spacing <= merge_boundary: // 1.0 <= 2.88? ✓
        return 4.5; // 固定高分
    
    // 3. 模糊區間線性遞減
    else:
        double zone_width = split_boundary - merge_boundary; // 14.52 - 2.88 = 11.64px
        double distance_from_merge = current_spacing - merge_boundary;
        double normalized_position = distance_from_merge / zone_width;
        double score = 4.0 - (normalized_position * 3.5); // 4.0 → 0.5 線性遞減
        
        return score;
```

### 具體計算步驟 (v3.4)
1.  **計算區間邊界:**
    - 合併區間上限：`2.4px + 0.48px = 2.88px`
    - 分割區間下限：`15px - 0.48px = 14.52px`
2.  **區間判斷:** `1.0px ≤ 2.88px`，落入**合併區間**。
3.  **固定評分:** 合併區間採用固定高分 `4.5` 分。

### 得分邏輯 (v3.4 雙峰區間)
- **合併區間 [0, peak_merge + tolerance]:** 固定高分 `4.5`，強烈合併信號。
- **分割區間 [peak_split - tolerance, ∞]:** 固定否決分 `-10.0`，強制分割。
- **模糊區間 (合併上限, 分割下限):** 線性遞減 `4.0 → 0.5`，越靠近合併邊界分數越高。

### 新邏輯優勢
- **智能區間劃分:** 保留雙峰模型的統計智能，能準確識別不同的間距模式。
- **評分邏輯簡化:** 區間內採用固定分數或簡單線性關係，計算高效。
- **決策清晰:** 明確的區間劃分讓決策過程更透明、可預測。
- **參數平衡:** 既利用統計特徵又簡化計算邏輯。

## Q3: 字體懲罰計算規則

**問題:** `字體懲罰：-0.40 (高度差異)` 中的 -0.40 分是怎麼計算出來的？公式是什麼？

**答案:**

### 計算公式 (基於規格文檔)
```pseudocode
function CalculateFontHeightPenalty(height1, height2):
    // 計算相對高度差異百分比
    double heightDiff = Math.Abs(height1 - height2) / Math.Min(height1, height2) * 100
    
    // 漸進式懲罰階梯
    if heightDiff <= 10%:       return 0.0   // OCR 微小誤差容錯範圍
    elif heightDiff <= 25%:     return 0.1   // 輕微差異
    elif heightDiff <= 50%:     return 0.4   // 中等差異  ← 對應-0.40分
    elif heightDiff <= 80%:     return 0.8   // 顯著差異
    elif heightDiff <= 120%:    return 1.2   // 大幅差異
    else:                       return 2.0   // 極大差異
```

### 具體計算示例
假設兩行文字的高度分別為：
- **前一行高度:** 20px
- **當前行高度:** 30px

**計算步驟:**
1. **高度差異:** |30 - 20| = 10px
2. **最小高度:** Min(20, 30) = 20px
3. **相對差異百分比:** (10 / 20) × 100 = 50%
4. **懲罰級別判定:** 50% 正好落在 `25% < heightDiff ≤ 50%` 區間
5. **懲罰分數:** 0.4 分 (在合併分數中以 -0.40 的形式扣分)

### 懲罰級別說明
- **0.0 分 (≤10%):** OCR 容錯範圍，同一字體的邊界框微小變異
- **0.1 分 (10-25%):** 同字體在不同渲染條件下的正常變化
- **0.4 分 (25-50%):** 相鄰字體大小級別的差異 ← 對應案例
- **0.8 分 (50-80%):** 明顯的字體大小差異
- **1.2 分 (80-120%):** 標題與正文的典型差異
- **2.0 分 (>120%):** 極端差異，強制分割級別

### 在最終合併分數中的作用
```
最終合併分數 = 距離得分 - 字體懲罰 - 對齊懲罰
例如: 4.75 - 0.40 - 0.00 = 4.35 分
```

## 補充說明

### 調試輸出格式規範
- **數值精度:** 所有分數保留兩位小數
- **計算順序:** 先計算各項得分，再進行加減運算
- **閾值比較:** 最終分數與動態閾值比較，決定合併或分割

### 參數調優建議
這些計算參數都可以根據實際測試結果進行微調，以達到最佳的版面分析效果。特別是：
- 雙峰調整係數 (0.2-0.3)
- 字體懲罰階梯閾值
- 動態基礎分設定 (2.0)
