## Q1: v3.1雙峰自適應閾值計算規則

**問題:** `v3.1雙峰自適應閾值：2.84 (動態基礎2.00 + 雙峰調整0.44 + 內容調整0.40)` 中的 2.00、0.44、0.40 這些數字是怎麼得出的？每項的評分標準是什麼？

**答案:**

### 動態基礎分 (2.00)
- **計算規則:** 這是系統的基準合併閾值，設定為固定值 `2.0` 分
- **設計理念:** 作為最基本的合併判斷標準，確保在沒有特殊情況下，合併分數需要超過 2 分才能進行段落合併
- **適用場景:** 適用於所有欄位，不論其雙峰特徵如何

### 雙峰調整分 (0.44)
- **計算公式:** `雙峰調整 = (peak_split - peak_merge) / peak_merge * 調整係數`
- **評分標準:**
  - **調整係數:** 通常為 0.2-0.3 之間
  - **計算邏輯:** 當雙峰差距越大時，說明該欄位的「段落內」和「段落間」特徵越分明，因此可以適當提高合併閾值，要求更嚴格的合併條件
  - **示例計算:** 假設 `peak_merge = 5px`, `peak_split = 15px`, 調整係數 = 0.22
    - `雙峰調整 = (15 - 5) / 5 * 0.22 = 2.0 * 0.22 = 0.44`

### 內容調整分 (0.40)
- **計算依據:** 基於欄位內容特徵的額外調整
- **評分標準:**
  - **字體大小變異度:** 欄位內字體高度變化越大 → 調整分越高 (0.1-0.3)
  - **對齊方式多樣性:** 欄位內包含多種對齊方式 → 調整分增加 (0.1-0.2)
  - **列表特徵檢測:** 如果檢測到列表特徵 → 調整分減少 (-0.1 至 -0.2)
  - **示例:** 字體變異 (0.2) + 對齊多樣 (0.1) + 其他因素 (0.1) = 0.40

### 最終閾值計算
`最終閾值 = 動態基礎 + 雙峰調整 + 內容調整 = 2.00 + 0.44 + 0.40 = 2.84`

## Q2: 強合併信號得分計算規則

**問題:** `合併區間：間距1.0px → 合併閾值2.4px → 強合併信號(3.00分)` 中的 3.00 分是怎麼計算出來的？

**答案:**

### 計算公式 (基於規格文檔偽代碼)
```pseudocode
function CalculateDistanceScore(current_spacing, peak_merge, peak_split, tolerance):
    // 假設: current_spacing = 1.0px, peak_merge = 2.4px, tolerance = 0.48px
    
    // 檢查是否落入合併區間
    if current_spacing <= peak_merge + tolerance:  // 1.0 <= 2.4 + 0.48 = 2.88 ✓
        // 計算與理想間距的偏差
        double distance = Math.Abs(current_spacing - peak_merge)  // |1.0 - 2.4| = 1.4
        double normalizedDistance = Math.Min(1.0, distance / tolerance)  // Min(1.0, 1.4/0.48) = 1.0
        double score = 4.0 - (normalizedDistance * 1.0)  // 4.0 - 1.0 = 3.0
        
        return score  // 3.00分
```

### 具體計算步驟
1. **間距歸類:** 1.0px ≤ 2.88px (peak_merge + tolerance)，確認為「合併區間」
2. **距離計算:** |1.0 - 2.4| = 1.4px (與理想間距的絕對偏差)
3. **標準化距離:** Min(1.0, 1.4/0.48) = 1.0 (偏差比例，最大為1.0)
4. **得分計算:** 4.0 - 1.0 = 3.0 分

### 得分邏輯
- **最高分 (4.0):** 當間距完全等於 `peak_merge` 時
- **最低分 (3.0):** 當間距與 `peak_merge` 的偏差等於或超過 `tolerance` 時
- **線性遞減:** 偏差越大，得分越低，但最低不會低於 3.0 分（合併區間保證分）

## Q3: 字體懲罰計算規則

**問題:** `字體懲罰：-0.40 (高度差異)` 中的 -0.40 分是怎麼計算出來的？公式是什麼？

**答案:**

### 計算公式 (基於規格文檔)
```pseudocode
function CalculateFontHeightPenalty(height1, height2):
    // 計算相對高度差異百分比
    double heightDiff = Math.Abs(height1 - height2) / Math.Min(height1, height2) * 100
    
    // 漸進式懲罰階梯
    if heightDiff <= 10%:       return 0.0   // OCR 微小誤差容錯範圍
    elif heightDiff <= 25%:     return 0.1   // 輕微差異
    elif heightDiff <= 50%:     return 0.4   // 中等差異  ← 對應-0.40分
    elif heightDiff <= 80%:     return 0.8   // 顯著差異
    elif heightDiff <= 120%:    return 1.2   // 大幅差異
    else:                       return 2.0   // 極大差異
```

### 具體計算示例
假設兩行文字的高度分別為：
- **前一行高度:** 20px
- **當前行高度:** 30px

**計算步驟:**
1. **高度差異:** |30 - 20| = 10px
2. **最小高度:** Min(20, 30) = 20px
3. **相對差異百分比:** (10 / 20) × 100 = 50%
4. **懲罰級別判定:** 50% 正好落在 `25% < heightDiff ≤ 50%` 區間
5. **懲罰分數:** 0.4 分 (在合併分數中以 -0.40 的形式扣分)

### 懲罰級別說明
- **0.0 分 (≤10%):** OCR 容錯範圍，同一字體的邊界框微小變異
- **0.1 分 (10-25%):** 同字體在不同渲染條件下的正常變化
- **0.4 分 (25-50%):** 相鄰字體大小級別的差異 ← 對應案例
- **0.8 分 (50-80%):** 明顯的字體大小差異
- **1.2 分 (80-120%):** 標題與正文的典型差異
- **2.0 分 (>120%):** 極端差異，強制分割級別

### 在最終合併分數中的作用
```
最終合併分數 = 距離得分 - 字體懲罰 - 對齊懲罰 + 重疊獎勵
例如: 3.00 - 0.40 - 0.00 + 0.00 = 2.60 分
```

## 補充說明

### 調試輸出格式規範
- **數值精度:** 所有分數保留兩位小數
- **計算順序:** 先計算各項得分，再進行加減運算
- **閾值比較:** 最終分數與動態閾值比較，決定合併或分割

### 參數調優建議
這些計算參數都可以根據實際測試結果進行微調，以達到最佳的版面分析效果。特別是：
- 雙峰調整係數 (0.2-0.3)
- 字體懲罰階梯閾值
- 動態基礎分設定 (2.0)
