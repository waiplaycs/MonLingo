Gaminik.dll 深度架構分析報告 (v2.0 增強版)
一、摘要 (Executive Summary)
Gaminik.dll 是 Gaminik 應用程式的核心 .NET 組件，基於 .NET Framework 4.8.1 和 Windows Presentation Foundation (WPF) 構建。分析顯示，該 DLL 並未經過高強度的混淆，其內部命名空間、類別和方法名稱清晰可辨，這為我們的逆向工程提供了極大的便利。

該組件的架構體現了關注點分離 (Separation of Concerns) 的設計原則，將 UI、業務邏輯、服務和資料模型劃分到不同的命名空間中。它作為總指揮，協調著底層原生引擎 (Native.dll)、多個線上翻譯 API、使用者帳戶系統以及複雜的 WPF 使用者介面。

核心發現：

混合式架構: 採用 .NET (主邏輯) + C++ (高效能任務) 的混合開發模式。

MVVM 設計模式: UI 層廣泛使用了 Model-View-ViewModel (MVVM) 模式的跡象，利用了如 Prism.Core 等框架來實現資料綁定和命令。

多引擎翻譯策略: 內建了對多種線上翻譯服務 (如 DeepL, Google) 和離線翻譯引擎 (CTranslate2) 的支援與切換邏輯。

完整的服務導向設計: 功能被封裝成各種服務，如 HotKeyService, ApiService, UpdateService 等，便於管理和擴充。

清晰的原生互通層: 存在一個專門的靜態類別，透過 P/Invoke ([DllImport]) 呼叫 Native.dll 中的所有匯出函式，是 .NET 與 C++ 之間的關鍵橋樑。

本報告將詳細拆解其內部結構，為 MonLingo 專案的開發提供具體的實現指導。

三、架構與命名空間分析 (Architectural Analysis)
Gaminik.dll 的程式碼結構清晰，透過命名空間進行了良好的組織。我們可以從中窺見其完整的系統架構。

Gaminik.Interface.*: 表現層 (Presentation Layer)

職責: 包含所有 WPF 視窗 (Window)、頁面 (Page) 和使用者控制項 (UserControl) 的定義。這是使用者直接互動的部分。

關鍵類別推斷: MainBarWindow, MainWindow, LoginWindow, CaptureRegionWindow, TranslationPopupWindow。從檔名 interface/mainbarwindow.baml 等可以佐證。

設計模式: 採用 MVVM 模式，每個 View (如 MainBarWindow.xaml) 都對應一個 ViewModel (如 MainBarWindowViewModel.cs)，透過資料綁定進行互動。

Gaminik.Service.*: 服務層 (Service Layer)

職責: 提供應用程式所需的各種背景服務和核心功能。

關鍵服務推斷:

ApiService: 負責所有與後端伺服器的網路通訊。

TranslateService: 翻譯功能的核心，內部包含切換不同翻譯引擎的邏輯。

HotKeyService: 監聽全域熱鍵以觸發翻譯。

ConfigService: 讀取和儲存使用者設定。

UpdateService: 檢查和下載應用程式更新。

LicenseService: 處理專業版授權和使用者登入狀態。

Gaminik.Core.*: 核心業務邏輯層 (Core Business Logic)

職責: 實現應用程式最核心的業務流程和演算法協調。

關鍵類別推斷:

NativeBridge (或類似名稱): 這是最關鍵的類別。它是一個靜態類別，包含了對 Native.dll 所有函式的 P/Invoke 宣告。

TranslationPipelineManager: 負責協調整個「擷取 -> OCR -> 翻譯 -> 顯示」的完整流程。

CaptureCoordinator: 專門管理擷取覆蓋層的顯示、隱藏和區域選擇邏輯。

Gaminik.Data.* / Gaminik.Model.*: 資料層 (Data Layer)

職責: 定義應用程式中使用的資料模型和資料存取邏輯。

關鍵類別推斷: User, Config, TranslationResult, GlossaryEntry, HistoryItem。

儲存技術: 使用了 Alampy.ManagedMmkv (高效鍵值儲存) 和 SQLitePCLRaw (本機資料庫)，分別用於儲存設定和歷史紀錄等。

四、核心工作流程推導 (Workflow Inference)
結合對 Native.dll 的分析，我們可以重建出 Gaminik 的核心即時翻譯工作流程。

4.1 即時 OCR 翻譯的技術實現細節 (新增)
這是一個典型的生產者-消費者模型，Native.dll (C++) 作為高頻率的影像生產者，Gaminik.dll (C#) 作為消費者和協調者。

啟動與熱鍵註冊:

在 App.xaml.cs 啟動時，HotKeyService 會透過 P/Invoke 呼叫 user32.dll 的 RegisterHotKey 函式來註冊全域熱鍵。

技術細節: 為了接收系統訊息，它會使用 WindowInteropHelper 獲取主視窗的控制代碼 (HWND)，並透過 HwndSource.AddHook 掛鉤到視窗的訊息迴圈，專門監聽 WM_HOTKEY (0x0312) 訊息。

觸發與擷取覆蓋層:

當熱鍵被觸發，CaptureCoordinator 會建立並顯示一個 WPF Window (CaptureRegionWindow)。

技術細節: 該視窗的屬性被設為 WindowStyle="None", AllowsTransparency="True", Topmost="True"，並設定一個半透明的背景，以實現全螢幕覆蓋效果。內部使用一個 Canvas 來處理 MouseDown, MouseMove, MouseUp 事件，讓使用者可以拖曳滑鼠來繪製選取框。

啟動原生擷取管線:

使用者選定區域後，CaptureCoordinator 獲取目標視窗的 HWND。

呼叫 NativeBridge.screenshot_window_loop_start(hwnd)。這一呼叫會啟動 C++ 層的非同步擷取管線。Native.dll 內部會註冊一個 FrameArrived 事件的回呼函式，此後由 Windows 系統在高頻率下（通常與螢幕刷新率同步）將新的 GPU 畫面訊框推送給這個回呼函式。

C# 層的消費迴圈:

Gaminik.dll 會啟動一個 System.Windows.Threading.DispatcherTimer。

技術細節: 這個計時器的間隔 (Interval) 可能被設定在一個較低的值（例如 100 毫秒）。在計時器的 Tick 事件中，C# 程式碼會執行以下操作：

呼叫 NativeBridge.screenshot_window_loop_read(buffer, ref size)，嘗試從 Native.dll 的共享緩衝區中拉取最新的影像資料（一個 byte[] 陣列）。

如果成功讀取到新的影像，則進入下一步。

OCR 與翻譯管線:

獲取的影像 byte[] 被傳遞給 NativeBridge.ocr_run_pipeline()。

技術細節: 此函式回傳一個 IntPtr，它是指向 C++ 記憶體中 OcrResult 物件的不透明指標。

C# 程式碼接著會：

呼叫 NativeBridge.ocr_get_line_count(resultPtr) 獲取結果中的行數。

使用一個 for 迴圈，遍歷每一行。

在迴圈中，呼叫 NativeBridge.ocr_get_line_content(resultPtr, i, stringBuilder, capacity)，將每一行的文字內容讀取到一個 StringBuilder 中。

【關鍵】: 完成所有資料讀取後，必須呼叫 NativeBridge.ocr_release_result(resultPtr) 來通知 C++ 層釋放該結果物件所佔用的記憶體，防止記憶體洩漏。

TranslateService 接收到組合好的 OCR 文字，非同步地呼叫線上 API 進行翻譯。

結果顯示與迴圈終止:

翻譯結果被設定到 TranslationPopupWindow 的 ViewModel 中，WPF 資料綁定機制自動更新 UI。

當使用者按下 Esc 或點擊其他地方，Gaminik.dll 會呼叫 NativeBridge.screenshot_window_close()，這會停止 C++ 層的擷取會話並清理資源。同時，C# 層的 DispatcherTimer 也會被停止。

六、結論與 MonLingo 開發建議
Gaminik.dll 是一個架構成熟、功能完整的 WPF 應用程式範例。它清晰地展示了如何將一個高效能的原生核心與一個功能豐富的 .NET UI 應用程式結合起來。

給 MonLingo 的具體開發建議:

嚴格遵循其架構分層: 在您的解決方案中，也建立 MonLingo.Core, MonLingo.Interface, MonLingo.Service 等專案，從一開始就保持程式碼的整潔。

優先實現 NativeBridge: 這是連接前後端的關鍵。首先定義好 C# 中的 static extern 函式簽名，這將成為您 C++ 引擎的開發規格。

全面採用 MVVM: 使用 CommunityToolkit.Mvvm (現代化的 MVVM 框架) 來處理所有 UI 互動，避免在 code-behind 中編寫大量邏輯。

實現服務的依賴注入 (Dependency Injection): 使用 .NET 內建的 IServiceCollection 來註冊您的所有服務，這將使您的應用程式更易於測試和維護。

專注於管線協調: TranslationPipelineManager 將是您 C# 程式碼中最複雜的部分，需要精心設計以處理非同步操作、錯誤和 UI 更新。
