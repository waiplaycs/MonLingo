## 🎯 功能概述

實現用戶要求：**"當前間距只要在全局平均間距以下都應當給一個剛好能合併的分數(比閾值多一點點)"**

## 📋 問題分析

### 原始問題
- 經驗規則通道中，策略三是唯一的加分項
- 當前間距在全局平均以下時，僅獲得+1.0分的低權重合併加分
- +1.0分常常不足以達到合併閾值，導致應該合併的行被分割

### 測試案例分析
```
策略評估開始 (行4-5): 間距=4.0px
- 全局平均間距: 5.6px
- 4.0px < 5.6px，應該獲得保證合併分數
- 原系統僅給+1.0分 → 分割 ❌
- 期望：給予足夠分數 → 合併 ✅
```

## 🚀 v4.4 解決方案

### 核心改進
在 `ExperienceRuleChannel.cs` 的 `EvaluateStrategy3Statistical` 方法中新增邏輯：

```csharp
else if (spacing <= globalMean)
{
    // v4.4新增：全局平均以下保證合併邏輯
    double guaranteedScore = dynamicThreshold + 0.1;
    double score = Math.Min(guaranteedScore, maxScore);
    
    AddDebugMessage($"全局平均保證合併+{score:F1} (確保合併成功) [v4.4新增]");
    return score;
}
```

### 技術實現細節

1. **方法簽名升級**
   ```csharp
   // v4.3
   private double EvaluateStrategy3Statistical(double spacing, double averageSpacing, double stdDeviation, double dynamicThreshold)
   
   // v4.4  
   private double EvaluateStrategy3Statistical(double spacing, double averageSpacing, double stdDeviation, double dynamicThreshold, ChannelStatistics globalStatistics)
   ```

2. **調用鏈更新**
   - `Process` → `PerformThreeStrategyScoring` → `EvaluateThreeStrategies` → `EvaluateStrategy3Statistical`
   - 所有方法均添加 `ChannelStatistics globalStatistics` 參數傳遞

3. **智能分數計算**
   - **基準**: 動態合併閾值 (如2.0分)
   - **保證值**: 動態閾值 + 0.1 (如2.1分)
   - **確保**: 略高於合併門檻，100%保證合併
