### 1.0 模組概述

本文件定義了 MonLingo 核心引擎中「高級版面分析 (Advanced Layout Analysis)」模組的演算法規格。

此模組的核心職責是接收來自 OCR 層的、原始且可能零散的文字辨識結果（包含文字內容及其邊界框座標），並將其智能地重組為一個結構化的、符合人類閱讀直覺的版面。最終輸出將清晰地劃分出畫面中的欄位 (Columns) 和段落 (Paragraphs)，為後續的翻譯和使用者介面渲染提供一個乾淨、有序的數據基礎。

本引擎採用三階段處理流程，以確保最高的準確性、穩健性與性能。

### 2.0 階段一：高效橫向行合併

此階段旨在高效解決 OCR 引擎可能將單行文字錯誤地分割為多個小框的問題，採用**簡化的相鄰合併策略**，確保邏輯清晰且性能優異。

### 2.1 演算法：迭代式順序合併 (Iterative Sequential Merging)

1.  **全局預排序 (Global Pre-sorting):**
    - **操作：** 在處理開始時，**立即對所有輸入的文字行進行全局的「從上到下、從左到右」雙重排序** (先按 Y 座標升序，Y 座標相同時再按 X 座標升序)。
    - **目的：** 這是後續所有高效掃描的基礎，確保處理順序符合閱讀直覺，並使演算法行為完全確定。時間複雜度為 `O(n log n)`。

2.  **迭代合併邏輯 (Iterative Merging Logic):**
    - **核心策略：** 採用一個主指針和一個前瞻指針來遍歷排序後的文字行列表。主指針標記當前合併鏈的起點，前瞻指針則不斷向後探索可合併的後續行。
    - **執行步驟：**
        1.  從第一行 (`line_i`) 開始，將其視為當前的「基礎行」。
        2.  檢查「基礎行」與緊鄰的下一行 (`line_j`) 是否滿足合併條件。
        3.  **如果滿足：** 將兩行合併為一個新的、更大的「基礎行」。接著，用這個新的「基礎行」繼續與下一行 (`line_k`) 進行比較，重複此過程，直到合併失敗為止。
        4.  **如果失敗：** 將最終合併完成的「基礎行」存入結果列表。主指針移動到合併鏈中最後一個被消耗行的下一行，開始新的合併探索。
        5.  重複以上步驟，直到所有行都被處理完畢。
    - **參數策略：** 採用**混合模式閾值系統**，在性能和準確性之間取得最佳平衡。

    - **關卡一 (垂直重疊率):**
        - **條件：** `垂直重疊高度 / min(line_i.Height, line_j.Height) > 0.6`
        - **解釋：** 確保兩個文字框在 Y 軸上的重疊度超過 **60%**。這是一個經過大量測試驗證的**固定閾值**，適用於絕大多數場景，避免了動態計算的開銷。

    - **關卡二 (相對水平間距):**
        - **條件：** `水平像素間距 < avg(line_i.Height, line_j.Height) * 1.5`
        - **解釋：** 確保兩個文字框的水平間距小於其平均高度的 **1.5倍**。這是一個**輕量級動態閾值**，能根據當前行的字體大小自適應調整，比固定像素值更具彈性。

### 2.2 輸出格式

階段一的輸出是一個經過合併處理的文字行列表。在這個列表中，原本在同一水平線上被分割的多個小文字框已經被合併成單一、完整的文字行。這個列表將作為階段二分欄處理的輸入。





### 3.0 階段二：單次遍歷智能分欄

此階段採用「單次遍歷有序聚類 (Single-Pass Ordered Clustering)」演算法，徹底消除重複掃描，確保每個文字行只被有效訪問一次，同時維持準確的分欄效果。

### 3.1 演算法：單次遍歷有序聚類 (Single-Pass Ordered Clustering)

**核心設計理念：**
- **消除重複掃描：** 每個文字行只會被處理一次，不會有任何重複的比較操作
- **活躍欄位管理：** 只維護當前「可能還會增長」的欄位列表，已確定不會再增長的欄位會被及時移除
- **即時歸屬判斷：** 每個新文字行會立即嘗試歸屬到現有的活躍欄位中，或創建新的欄位

### 3.2 執行流程

**前提條件：** 階段一已完成全局預排序，所有文字行已按「從上到下、從左到右」的順序排列。

#### **步驟2：單次遍歷 (Single Pass)**

```pseudocode
// 初始化活躍欄位管理列表
active_columns = []  // 存放當前所有「活躍」的欄位
completed_columns = []  // 存放已完成的欄位

// 只使用一個 for 循環遍歷所有行
for each line_i in sorted_lines:
    assigned = false  // 標記當前行是否已被歸屬
    
    // 嘗試將 line_i 歸屬到某個活躍欄位
    proceed_to_ownership_check(line_i)
```

#### **步驟3：歸屬判斷 (Ownership Check)**

```pseudocode
function proceed_to_ownership_check(line_i):
    // 遍歷所有活躍的欄位
    for each column_j in active_columns:
        // 判斷 line_i 是否可以被歸入 column_j
        if can_assign_to_column(line_i, column_j):
            // 成功歸屬：將 line_i 添加到 column_j
            column_j.add_line(line_i)
            column_j.update_boundaries()  // 更新欄位邊界
            assigned = true
            break  // 找到歸屬後立即跳出
    
    // 如果無法歸入任何活躍欄位，創建新欄位
    if not assigned:
        new_column = create_new_column(line_i)
        active_columns.append(new_column)
    
    // 執行欄位修剪檢查
    perform_column_pruning(line_i)
```

**歸屬判斷標準：**

歸屬判斷函數採用兩個核心檢查標準來確保文字行與欄位的兼容性：

**垂直鄰近度檢查：** 系統會計算當前文字行與目標欄位中所有現有文字行之間的最小垂直距離。如果這個最小距離超過**欄位內平均行高的1.5倍**，則認為垂直間距過大，歸屬判斷失敗。這個輕量級動態閾值確保了欄位內部文字行之間保持合理的垂直連續性，並能有效處理包含小字型行（如日期、標題）的混合字體文檔。**[v3.5優化]**

**水平重疊度檢查：** 系統會計算當前文字行與目標欄位邊界框之間的水平重疊範圍，然後計算重疊比例（重疊寬度除以兩者寬度的較小值）。如果重疊比例小於**50%**，則認為水平對齊度不足，歸屬判斷失敗。這個固定閾值確保了欄位內部的文字行在水平方向上保持良好的對齊性。

只有同時通過這兩個檢查的文字行才會被認為可以歸屬到目標欄位中。

#### **步驟4：索引穩定性欄位修剪 (Index-Stable Column Pruning)** **[v3.5優化]**

**目標：** 及時識別並標記不可能再增長的欄位，減少後續無效的比較操作，同時維持索引穩定性。

在處理每個文字行後，系統會檢查活躍欄位列表，判斷是否有任何欄位因為垂直距離過遠而不可能再有新成員加入。

**v3.5索引穩定性改進：**
- **修剪策略轉變：** 從物理移除欄位改為使用**修剪標記陣列 (`prunedColumns`)**，避免索引混亂
- **處理時機調整：** 修剪檢查在歸屬檢查之前執行，確保調試輸出與實際邏輯同步
- **歸屬檢查優化：** 自動跳過已標記為修剪的欄位，避免無效比較

**混合修剪條件：**
系統會計算當前文字行與每個活躍欄位底部之間的垂直距離。如果這個距離超過了**基於全局平均行間距計算出的動態閾值（平均行間距的3倍）**，則該欄位會被標記為已修剪，但不從列表中物理移除。

```pseudocode
// v3.5索引穩定性修剪實現
function perform_column_pruning_v3_5(current_line):
    for i in range(len(active_columns)):
        if not prunedColumns[i]:  // 只檢查尚未修剪的欄位
            distance = calculate_vertical_distance(current_line, active_columns[i])
            threshold = global_avg_line_spacing * 3.0
            if distance > threshold:
                prunedColumns[i] = true  // 標記為已修剪，不物理移除
```

這個索引穩定性策略能有效適應不同疏密程度的文檔，同時確保後續歸屬檢查的索引一致性，避免了v3.4及以前版本中的「行11跳過欄位1」等索引混亂問題。

### 4.1  階段三 演算法：混合模式段落檢測 (Hybrid Paragraph Detection)

#### 步驟一：內容類型預檢查 (Content Type Pre-analysis)

在對欄位進行分割前，系統會首先進行快速的內容特徵分析，以決定最高效的處理策略。

1.  **單行欄位捷徑 (Single-Line Shortcut):**
    - **條件：** 如果一個欄位僅包含單一文字行。
    - **操作：** 系統會立即將該行視為一個獨立段落，並跳過所有後續的分割邏輯。這是針對UI按鈕、標籤等單行元素的關鍵性能優化。

2.  **列表項目識別 (List Item Detection):**
    - **條件：** 如果欄位中的多行文字呈現出明顯的列表特徵（如相似的縮排、以 `*`, `-`, `1.` 等符號開頭）。
    - **操作：** 系統將啟用基於縮排和列表符號的快速分割邏輯，將每個列表項視為一個獨立段落。

3.  **連續文本處理 (Continuous Text Handling):**
    - **條件：** 如果欄位內容不符合以上特徵，則被視為標準的連續文本。
    - **操作：** 系統將採用下一步的「多指標加權決策系統」進行精細分割。

#### 步驟二：智能通道選擇器 (Intelligent Channel Selector)

**版本提升：** v4.0 - 雙通道決策架構整合，應對數據不確定性

##### 核心理念：應對數據不確定性的智能決策

在版面分析中，並非所有內容都擁有足夠的統計樣本來支持複雜的算法模型。例如，一個僅有數行的文本塊，無法有效形成「雙峰分佈」。強行使用統計模型處理這類「低可信度」數據，結果往往不可靠。

為解決此問題，我們引入了 **「雙通道決策架構 (Dual-Channel Decision Architecture)」**。

##### 通道選擇邏輯

「通道選擇器」在對欄位進行段落分割前，會進行快速的預檢查，以決定進入哪個分析通道：

###### 觸發「經驗規則通道」的條件

當以下**任一條件**被滿足時，系統將判定當前數據為「低可信度」，並切換到「經驗規則通道」：

1.  **樣本數量不足:**
    - **條件:** `總間距數量 < 8` (經驗值，可調)
    - **原因:** 統計樣本過少，無法形成有意義的分佈。

2.  **峰值模式不明顯:**
    - **條件:** `有效峰值數量 < 2`
    - **原因:** 無法找到「段落內」和「段落間」兩種清晰的間距模式。

3.  **峰值區分度低:**
    - **條件:** `peak_split / peak_merge ≤ 1.5`
    - **原因:** 兩個峰值距離太近，統計上無法有效區分，強行使用會導致決策模糊。

###### 觸發「雙峰統計通道」的條件

如果**不滿足**上述任何一個「經驗規則通道」的觸發條件，系統將默認進入常規的**「雙峰統計通道」**，利用其強大的統計分析能力處理數據。

#### 步驟三：雙峰統計通道 - 穩健的雙峰驅動標準行距計算模型

**版本提升：** v4.0 - 基於 v3.5 的改進，整合雙通道架構

##### 問題背景

在 `v3.0` 規格中，採用**中位數 (Median)** 作為核心指標。然而，當一個欄位內存在多種合法的行距模式時（即「多峰分佈」，例如，同時包含緊湊的列表項和常規的段落文本），單純的中位數會被數量佔優的數據簇「拉偏」，導致計算出的「標準行距」失去代表性，進而影響後續加權決策的準確性。

##### 核心思想轉變

我們將行距的判斷從「與單一標準比較」升級為「**判斷當前行距歸屬於哪種排版模式**」。

基於一個核心觀察：
*   **小間距峰值 (`peak_merge`)**: 代表「段落內部」的標準行距，是**強烈的合併信號**。
*   **大間距峰值 (`peak_split`)**: 代表「段落之間」的間距，是**強烈的分割信號**。

##### 步驟 3.1：多峰識別與關鍵角色分配 (Multi-Peak Identification & Key Role Assignment)

在進入加權決策系統前，首先對欄位內的所有相鄰行間距進行分析，以識別出扮演關鍵角色的 `peak_merge` 和 `peak_split`。

1.  **收集與排序**:
    *   計算欄位內所有相鄰行的垂直間距 `spacings`，並升序排列。
    *   **v4.0 重要改進**: **保留負間距值**（當 `currentLine.Top < prevLine.Bottom` 時），這些負值代表文字行重疊，是OCR錯誤或密集排版的重要特徵信號，將參與雙峰模型分析以提高合併決策的準確性。

1.5. **值域轉換防護機制 (v4.5 負間距魯棒性增強)**:
    *   **核心問題**: 保留負間距值雖然保留了文字重疊信息，但會導致後續聚類和變異係數計算出現數學異常：
        - **平均值可能為負或接近零**：導致變異係數計算除零錯誤或負CV值
        - **峰值可能為負**：雖然負峰值本身有意義（表示重疊），但需要後續步驟正確處理
    *   **解決方案 - 值域轉換（Domain Shift）**:
        - **原理**: 將所有間距值同步平移相同偏移量，使最小值變為0，但**保持所有相對關係不變**
        - **數學公式**: `adjusted_spacing = original_spacing - min_spacing`
        - **關鍵特性**: 
            - 間距差值（gaps）完全不受影響：`gap_adjusted = gap_original`
            - 聚類結果數學等價：簇的相對位置和大小不變
            - 統計計算安全：平均值≥0，變異係數計算不會除零或為負
    *   **應用時機**: 
        - **閾值計算階段**: `CalculateClusterThreshold` 檢測到 `min_spacing < 0` 時自動應用
        - **聚類分析階段**: `AnalyzePeaks` 使用轉換後數據進行聚類
    *   **峰值處理**: 
        - **內部計算**: 使用轉換後數據計算峰值（保證非負）
        - **外部輸出**: 將峰值轉換回原始值域 `peak_original = peak_adjusted - offset`
        - **語義保持**: 輸出的峰值保留負值語義（表示文字重疊）
    
    **值域轉換示例：**
    ```
    原始間距序列: [-8, -7, -6, -5, 2, 3, 4, 5]
    min_spacing = -8
    offset = -(-8) = 8
    
    轉換後序列: [0, 1, 2, 3, 10, 11, 12, 13]
    
    聚類結果（基於轉換後數據）:
    ```

2.  **基於密度的一維聚類 (v4.1 自適應閾值改進) - 雙峰模型前的關鍵預處理**:
    *   **核心目的**: **劃分山峰 (Peak Identification)**，為後續雙峰模型提供準確的統計基礎。
    *   **聚類閾值 (`cluster_threshold`)**: 定義一個動態閾值來判斷兩個相鄰間距值是否屬於同一類，**這是識別不同間距模式的關鍵步驟**。
    *   **v4.1 重大改進 - 混合自適應閾值策略**：為解決固定倍數（0.25）在不同文檔密度下的敏感性問題，採用雙階段智能分析來**精確劃分山峰**：
        1. **階段一 - 自然間隙分析法**：分析相鄰間距差值序列，尋找最大"自然斷點"作為閾值。**類比：如同在山脈中尋找最明顯的峽谷來劃分山峰**。
        2. **階段二 - 變異係數校驗法**：當自然間隙不明顯時，使用統計離散度指標進行補償校驗。**類比：如同氣象學家在雲層密佈時改用氣壓變化來劃分天氣系統**。
    *   **舊版兼容性**: 若兩階段方法均失效（極端邊緣情況），則回退到經典固定倍數：`欄位平均字體高度 * 0.25`。
    *   **遍歷與聚類**: 遍歷排序後的 `spacings` 列表。如果相鄰兩個間距的差值小於 `cluster_threshold`，則將它們歸為同一簇；否則，創建新簇。**此步驟的輸出將直接決定雙峰模型的質量**。

    **v4.1 自適應閾值計算詳細規格：**
    
    *階段一：自然間隙分析法 (Gap-Based Analysis)*
    ```csharp
    private double CalculateGapBasedThreshold(List<double> sortedSpacings)
    {
        if (sortedSpacings.Count < 3) return double.NaN;
        
        // 計算相鄰間距的差值序列
        List<double> gaps = new List<double>();
        for (int i = 1; i < sortedSpacings.Count; i++)
        {
            gaps.Add(sortedSpacings[i] - sortedSpacings[i - 1]);
        }
        
        // 尋找最大間隙作為"自然斷點"
        double maxGap = gaps.Max();
        double avgGap = gaps.Average();
        
        // 驗證最大間隙是否"顯著"（是平均間隙的2倍以上）
        if (maxGap >= avgGap * 2.0)
        {
            return maxGap * 0.6; // 使用最大間隙的60%作為閾值
        }
        
        return double.NaN; // 自然間隙不明顯，需要階段二補償
    }
    ```
    
    *階段二：變異係數校驗法 (Coefficient of Variation Method)*
    ```csharp
    private double CalculateAdaptiveThreshold(List<double> sortedSpacings, double avgFontHeight)
    {
        if (sortedSpacings.Count < 2) return avgFontHeight * 0.25;
        
        double mean = sortedSpacings.Average();
        double variance = sortedSpacings.Select(x => Math.Pow(x - mean, 2)).Average();
        double stdDev = Math.Sqrt(variance);
        double coefficientOfVariation = stdDev / mean;
        
        // 根據數據離散程度動態調整閾值倍數
        double adaptiveFactor;
        if (coefficientOfVariation > 0.8)        // 高離散度：使用較大閾值
            adaptiveFactor = 0.35;
        else if (coefficientOfVariation > 0.4)   // 中等離散度：標準閾值
            adaptiveFactor = 0.25;
        else                                     // 低離散度：使用較小閾值
            adaptiveFactor = 0.15;
        
        return avgFontHeight * adaptiveFactor;
    }
    ```
    
    *混合策略整合邏輯*

    {

3.  **關鍵峰值定義 (Key Peak Definition)**:
    *   從聚類結果中過濾掉成員數量過少的「噪音簇」（例如，成員數 ≤ 1），提取所有有效峰值（簇的均值），並按大小排序得到 `peaks = [p1, p2, ..., pn]`。
    *   **噪音簇記錄 (v4.0 新增)**：系統會在調試輸出中詳細記錄被過濾掉的噪音簇信息，包括成員數量和具體的間距值，以便於算法分析和調試驗證。這些噪音簇通常是單點間距值，不具統計意義，但記錄它們有助於理解數據分佈特徵。
    
    *   **噪音簇過濾的影響範圍詳解 (v4.6 技術驗證)**:
    
        **核心結論**: 噪音簇過濾**只影響峰值定義和通道選擇兩個部分**，原始間距數據完整保留並參與所有後續計算。
        
        **影響範圍總結表**:
        | 處理階段 | 是否受影響 | 實際影響 |
        |---------|-----------|---------|
        | 間距數據收集 | ❌ 不受影響 | 所有間距值完整保留（包括孤立極端值） |
        | **峰值定義** | ✅ **受影響** | 噪音簇不參與`peak_merge`和`peak_split`計算 |
        | **通道選擇** | ✅ **受影響** | 基於「有效峰值數量」判斷使用哪個通道 |
        | 區間定義 | ❌ 不受影響 | 使用有效峰值定義區間，邏輯正確 |
        | 評分計算 | ❌ 不受影響 | 使用原始間距值進行評分 |
        | 合併決策 | ❌ 不受影響 | 基於評分結果決策 |
        | 全局統計 | ❌ 不受影響 | 使用所有原始間距計算平均值/標準差 |

        - ✅ **評分使用原始值**: 孤立極端值（如100px章節間距）仍參與評分並觸發強分割信號

        如果不過濾噪音簇，會導致以下嚴重問題:
        
        1. **峰值被污染**: OCR錯誤產生的-50px異常值會成為`peak_merge`，扭曲統計意義
        2. **統計失真**: 孤立極端值不代表任何常規模式，卻影響峰值計算
        3. **噪音簇激增**: 小幅抖動（2.1, 2.2, 2.3...）產生大量單點簇，喪失統計錨點功能
        4. **區間計算異常**: 極端噪音作為`peak_split`導致決策邊界失真

        | 場景 | 過濾噪音簇（當前設計） | 不過濾噪音簇 |
        |------|-------------------|------------|
        | 峰值純度 | ✅ 代表常規模式 | ❌ 被極端值污染 |
        | 統計意義 | ✅ 基於有效聚類 | ❌ 孤立點混入 |
        | 決策完整性 | ✅ 評分時處理所有值 | ⚠️ 依然處理所有值 |
        | 極端值處理 | ✅ 通過區間判斷識別 | ⚠️ 作為峰值扭曲區間 |
        | 章節間距100px | ✅ -10.0強分割 | ❌ 可能成為峰值導致誤判 |
        
        **最終結論**: 
        - 噪音簇過濾**正確實現了職責分離**
        - 峰值定義 = 代表常規模式的統計錨點（需要純度保護）
        - 實際決策 = 處理每個間距值（需要完整性保證）
        - 當前設計達到了**統計純度**與**決策完整性**的最優平衡 ✅
    
    *   **定義 `peak_merge`**: `peak_merge` **永遠是最小的峰值 `p1`**。它代表了文檔中最緊密的合法間距，是最強的合併信號來源。
    *   **定義 `peak_split`**: `peak_split` **永遠是最大的峰值 `pn`**。它代表了文檔中最顯著的間距，是分割段落的主要依據。
    *   **中間峰值處理**: 所有中間的峰值 (`p2` 到 `pn-1`) 將自然落入後續定義的「模糊區間」，其決策將依賴其他指標（字體、對齊等），這符合將不確定性交給多指標系統處理的原則。

##### 步驟 3.2：定義決策區間（僅限雙峰統計通道）- 為分數計算建立統計基礎

**目的說明**: 利用步驟3.1識別出的兩個關鍵峰值作為錨點，定義三個核心決策區間。**這些區間將直接用於後續步驟3.3中計算"雙峰驅動距離得分"**，是整個評分系統的統計基礎。

*   **容差 (`tolerance`)**: **v4.5 改進**：必須使用絕對值計算容差以保證為正數：`tolerance = |peak_merge| * 0.2`。
    - **原因**: 當 `peak_merge` 為負值（文字重疊）時，直接乘以0.2會得到負容差，導致區間邊界計算錯誤。
    - **示例**: `peak_merge = -0.67` → `tolerance = |-0.67| × 0.2 = 0.134` ✅

**v4.5 動態區間規則（支持負峰值）**:

根據 `peak_merge` 的正負值，採用不同的區間劃分策略以正確處理文字重疊情況：

**情況A：正常情況 (`peak_merge ≥ 0`)**

1.  **合併區間 (Merge Zone)**
    *   **範圍**: `[0, peak_merge + tolerance]`
    *   **語義**: 從"無間距"到"段內峰值+容差"的正常合併範圍
    *   **意義**: 間距符合「段落內部」模式，**將在步驟3.3中獲得高分 (4.5分)**。

2.  **模糊區間 (Ambiguity Zone)**
    *   **範圍**: `(peak_merge + tolerance, peak_split - tolerance)`
    *   **語義**: 介於段內和段間峰值之間的不確定區域
    *   **意義**: 間距落在兩種模式之間，本身不提供明確信號，**將在步驟3.3中使用線性遞減評分**。

3.  **分割區間 (Split Zone)**
    *   **範圍**: `[peak_split - tolerance, ∞)`
    *   **意義**: 間距符合「段落之間」模式，**將在步驟3.3中獲得否決分 (-10.0分)**。

**情況B：重疊情況 (`peak_merge < 0`)**

當 `peak_merge` 為負值時，表示文字行存在重疊（OCR錯誤或密集排版）。此時需要調整區間劃分邏輯：

1.  **合併區間 (Merge Zone)**
    *   **範圍**: `[peak_merge, 0 + tolerance]`
    *   **語義**: 從"重疊峰值"到"無間距+容差"的擴展合併範圍
    *   **意義**: 涵蓋整個重疊區域和輕微正間距，**將在步驟3.3中獲得高分 (4.5分)**。
    *   **示例**: `peak_merge = -0.67`, `tolerance = 0.13` → 合併區間 `[-0.67, 0.13]`

2.  **模糊區間 (Ambiguity Zone)**
    *   **範圍**: `(0 + tolerance, peak_split - tolerance)`
    *   **語義**: 從"無間距+容差"開始到分割邊界的模糊區域
    *   **關鍵變化**: 起點不再是 `peak_merge + tolerance`（會是負值），而是 `0 + tolerance`
    *   **意義**: **將在步驟3.3中使用線性遞減評分**。
    *   **示例**: `tolerance = 0.13`, `peak_split = 13.40` → 模糊區間 `(0.13, 13.27)`

3.  **分割區間 (Split Zone)**
    *   **範圍**: `[peak_split - tolerance, ∞)`
    *   **意義**: 與正常情況相同，**將在步驟3.3中獲得否決分 (-10.0分)**。

**區間劃分決策邏輯（代碼實現）：**
```csharp
double tolerance = Math.Abs(peak_merge) * 0.2;  // 容差必須為正數
double mergeStart, mergeBoundary, ambiguityStart;

if (peak_merge >= 0) {
    // 正常情況
    mergeStart = 0;
    mergeBoundary = peak_merge + tolerance;
    ambiguityStart = mergeBoundary;
} else {
    // 重疊情況
    mergeStart = peak_merge;  // 允許負值起點
    mergeBoundary = 0 + tolerance;
    ambiguityStart = 0 + tolerance;  // 從0+容差開始
}

double splitBoundary = peak_split - tolerance;
```

##### 步驟3.3：雙峰驅動的多指標加權決策系統 - 計算最終合併分數

**核心目的**: 綜合多個維度的特徵來計算「合併分數」，此分數將與步驟3.4的「合併閾值」進行比較，決定是否合併相鄰行。**這是雙峰統計通道的核心計算步驟**。

此步驟專為連續文本設計，它不再依賴單一的行距指標，而是基於步驟3.1和3.2建立的雙峰模型，重新設計了距離得分計算邏輯。

- **核心策略：** 遍歷欄位中的每一行，計算當前行 `line_i` 與上一行 `line_i-1` 之間的「合併分數」。**採用加減分混合制度，分數從基礎分開始，根據各項指標進行加分或減分**。
- **與閾值比較**: 計算出的分數將與步驟3.4得出的「合併閾值」比較：如果分數**超過**閾值，則兩行保持在同一段落；如果分數**低於**閾值，則在此處創建新段落。

- **合併分數計算模型 (v3.3 簡化公式):**
    `合併分數 = 雙峰驅動距離得分 - 字體高度懲罰 - 對齊風格懲罰`

    1.  **雙峰驅動距離得分 (Bi-Peak Driven Distance Score) - 主要得分項**:
        - **計算邏輯：** **v3.4 雙峰區間簡化改進**：使用步驟3.2定義的區間進行評分，各區間採用固定分數或線性遞減，邏輯清晰直觀。
        - **這是最主要的得分項，直接使用雙峰模型的統計結果**。
        
        ```pseudocode
        function CalculateDistanceScore(current_spacing, peak_merge, peak_split, tolerance):
            // v4.0 雙通道架構：此函數僅在雙峰統計通道中執行
            // 通道選擇器已在此之前確保統計樣本充足
            
            // v3.4 雙峰區間劃分 + 簡化評分
            // 注意：current_spacing 可能為負值（重疊情況）
            
            // 1. 強分割信號：落入分割區間
            if current_spacing >= peak_split - tolerance:
                return -10.0; // 固定否決分，強制分割
            
            // 2. 強合併信號：落入合併區間（包含負值重疊）
            if current_spacing <= peak_merge + tolerance:
                return 4.5; // 固定高分，強烈合併信號
            
            // 3. 模糊區間：線性遞減評分
            // 範圍：(peak_merge + tolerance, peak_split - tolerance)
            else:
                double merge_boundary = peak_merge + tolerance;
                double split_boundary = peak_split - tolerance;
                double zone_width = split_boundary - merge_boundary;
                
                // 防止除零錯誤
                if zone_width <= 0:
                    return 2.0; // 當兩個區間重疊時的默認分數
                
                // 線性遞減：從合併邊界的4.0分遞減到分割邊界的0.5分
                double distance_from_merge = current_spacing - merge_boundary;
                double normalized_position = distance_from_merge / zone_width; // [0, 1]
                double score = 4.0 - (normalized_position * 3.5); // 4.0 → 0.5 線性遞減
                
                return score;
        ```
        
        - **解釋：** **這是最主要的得分項**。保留雙峰模型的智能區間劃分優勢：合併區間給予固定高分 4.5，分割區間給予固定否決分 -10.0，模糊區間採用線性遞減（越靠近合併邊界分數越高）。邏輯清晰、行為可預測，同時保持統計模型的智能性。

    2.  **字體高度懲罰 (Font Height Penalty) - 漸進式容錯模型:**
        - **計算邏輯：** 採用漸進式懲罰機制，考慮 OCR 框架誤差與真實字體差異：
        
        ```pseudocode
        function CalculateFontHeightPenalty(height1, height2):
            // 計算相對高度差異百分比
            double heightDiff = Math.Abs(height1 - height2) / Math.Min(height1, height2) * 100
            
            // 漸進式懲罰階梯
            if heightDiff <= 10%:
                return 0.0        // OCR 微小誤差容錯範圍，無懲罰
            elif heightDiff <= 25%:
                return 0.1        // 輕微差異，可能是同字體的 OCR 變異
            elif heightDiff <= 50%:
                return 0.4        // 中等差異，可能是相鄰字體級別
            elif heightDiff <= 80%:
                return 0.8        // 顯著差異，不同字體級別
            elif heightDiff <= 120%:
                return 1.2        // 大幅差異，標題與正文級別
            else:
                return 2.0        // 極大差異，強制分割級別
        ```
        
        - **設計理念：**
          - **OCR 容錯 (≤10%)**: 考慮到 OCR 引擎對同一字體可能產生的邊界框微小變異，給予完全容錯。
          - **同字體變異 (10-25%)**: 可能是同一字體在不同渲染條件下的正常變化，僅給予輕微懲罰。
          - **相鄰級別 (25-50%)**: 相鄰字體大小級別的典型差異範圍，中等懲罰。
          - **不同級別 (50-80%)**: 明顯的字體大小差異，較重懲罰。
          - **標題級別 (80-120%)**: 標題與正文的典型差異，重度懲罰。
          - **極端差異 (>120%)**: 可能是裝飾文字或特殊元素，給予最高懲罰以強制分割。
        
        - **解釋：** **智能字體差異識別項**。通過漸進式懲罰機制，能夠準確區分 OCR 誤差與真實字體變化，避免因微小的邊界框差異而錯誤分割同一段落，同時對真正的字體大小變化給予適當的分割信號。

    3.  **對齊風格懲罰 (Alignment Style Penalty):**
        - **計算：**
          - 如果對齊風格相同：懲罰 `0`
          - 如果對齊風格不同：懲罰 `0.2`
        - **解釋：** **對齊不一致懲罰項**。對齊風格不一致時給予扣分。此項用於識別不同段落的對齊特徵差異，防止左對齊和居中對齊的行被錯誤合併。

- **決策流程與閾值比較：**
    - 在遍歷過程中，系統會計算每一對相鄰行的「合併分數」。
    - 計算出的分數將與步驟3.4動態計算的「合併閾值」進行比較：
      - 如果**合併分數 > 合併閾值** → 將 `line_i` **合併**到當前段落中
      - 如果**合併分數 ≤ 合併閾值** → 在 `line_i` 處**創建新段落**

##### 步驟3.4：v4.2智能自適應合併閾值計算 - 確定合併及格線

**核心目的**: **計算合併決策的"及格線"**，即確定步驟3.3計算出的合併分數需要達到多少才算"及格"並執行合併操作。**這是整個雙峰統計通道的最終決策環節**。

**v4.2模糊區間中點評分閾值系統 (Ambiguity Zone Midpoint Score Threshold):**
    
    **版本演進：** v3.0固定閾值 → v3.1動態統計閾值 → v4.2模糊區間中點評分閾值
    
    **問題背景：**
    早期版本使用固定閾值（如v3.0的2.5）無法適應不同文檔特性。v3.1嘗試引入基於統計分佈的複雜動態計算（IQR、變異係數、可信度評分等），但實測發現：
    1. **統計公式產生的閾值位置不合理** - 容易過度偏向合併邊界或分割邊界
    2. **複雜計算反而降低可解釋性** - 多層加權疊加後，決策邏輯難以追溯
    3. **對極端案例缺乏幾何直觀性** - 在模糊區間內的間距應該有明確的公平決策點

    **🎯 v4.2核心策略：模糊區間中點對應的評分值作為閾值**

    **設計理念：評分系統與決策點完美對齊**
    > 步驟3.3已經建立了線性評分系統：模糊區間內從4.0分（合併邊界）線性遞減到0.5分（分割邊界）。
    > v4.2的關鍵洞察：**位於模糊區間幾何中點（50%位置）的間距，其評分值就是最公平的合併閾值**。
    > 
    > - **模糊區間50%位置** → 評分值 = (4.0 + 0.5) / 2 = **2.25分**
    > - **這個2.25分就是合併及格線**：
    >   - 分數 ≥ 2.25 → 更接近合併邊界 → 執行合併
    >   - 分數 < 2.25 → 更接近分割邊界 → 執行分割

    **實測案例分析：**

#### 步驟四：經驗規則通道 - 基於多策略加減分的合併評分系統

**版本提升：** v4.0 - 雙通道架構核心組件，專門處理統計不足的低可信度數據

**🔄 通道定位說明：**
- **觸發條件**: 當步驟二智能通道選擇器判定數據為「低可信度」時自動觸發
- **與步驟三關係**: **互斥關係** - 進入此通道的欄位將**完全跳過步驟三**的雙峰統計處理
- **處理目標**: 專門處理統計樣本不足、間距模式模糊、或結構高度一致的內容
- **輸出結果**: 直接產生段落分割決策，與步驟三具有相同的功能定位

##### 引言：何時需要經驗規則通道？

當雙峰統計模型因為數據不足或模式模糊而失效時，「經驗規則通道」將被激活。這通常發生在以下幾種特徵的欄位中：

1.  **結構高度一致的內容 (Highly Structured & Uniform Content):**
    - **特徵:** 行間距高度統一，只有一個統計峰值。
    - **案例:** 列表、UI選單、代碼塊、表格。

2.  **內容極簡的欄位 (Minimalist Content Columns):**
    - **特徵:** 行數太少（例如少於8行），無法提供足夠的統計樣本。
    - **案例:** 標題、圖片說明、簡短提示。

3.  **間距模式模糊的內容 (Ambiguous Spacing Patterns):**
    - **特徵:** 段內和段間距非常接近，無法清晰分離出兩個峰值。
    - **案例:** 高密度排版（如法律文件）、格式混亂的文本。

當數據被判定為「低可信度」時，系統不再依賴行距的統計分佈，而是轉向分析更穩定、更具體的局部特徵。它會像一個經驗豐富的排版師，通過觀察以下線索來計算「合併分數」。

##### 評分總則｜以合併為目標的加減分

- **分數起點:** 從 `0` 開始累積，允許「加分與扣分」。
- **訊號處理:** 支援合併的線索→加分；不利合併（暗示分割）的線索→扣分；若遇到強分割線索→採用「硬性分割」直接終止合併判定。
- **合併判定:** 當最終合併分數達到或超過「合併閾值」即判定合併；未達則分割。


##### 策略一：基於字體層次的扣分 (Font Hierarchy) - 漸進式容錯模型 🔄 [v4.4更新]

- **類比:** 通過制服大小和樣式識別職位層級，但考慮測量誤差的寬容度。
- **規則:** 比較相鄰兩行的字體大小，採用漸進式懲罰機制，考慮OCR框架誤差與真實字體差異。
- **評分機制（扣分項）:** [v4.4更新 - 參考雙峰通道字體高度懲罰機制]
    - **無扣分 (0分):** 字體大小相對差異 ≤ 10%（OCR微小誤差容錯範圍）
    - **極輕扣分 (-0.1分):** 相對差異 10% - 25%（輕微差異，可能是同字體的OCR變異）
    - **輕度扣分 (-0.4分):** 相對差異 25% - 50%（中等差異，可能是相鄰字體級別）
    - **中度扣分 (-0.8分):** 相對差異 50% - 80%（顯著差異，不同字體級別）
    - **重度扣分 (-1.2分):** 相對差異 80% - 120%（大幅差異，標題與正文級別）
    - **極重扣分 (-2.0分):** 相對差異 > 120%（極大差異，強制分割級別）

**設計理念：** [v4.4更新]
- **OCR容錯 (≤10%)**: 考慮OCR引擎對同一字體可能產生的邊界框微小變異，給予完全容錯
- **同字體變異 (10-25%)**: 可能是同一字體在不同渲染條件下的正常變化，僅給予極輕微懲罰
- **相鄰級別 (25-50%)**: 相鄰字體大小級別的典型差異範圍，輕度懲罰
- **層次差異 (50%+)**: 明顯的字體層次變化，逐步加重懲罰直至強制分割

##### 策略二：基於對齊模式的扣分 (Alignment Patterns)

- **類比:** 觀察隊伍的排列規律，識別是否有人換列或縮進。
- **規則:** 檢測相鄰兩行是否存在顯著的縮排變化或對齊方式切換。
- **評分機制（扣分項）:**
    - **無扣分 (0分):** 左邊界 X 差異小於一個字符寬度，且對齊方式一致。
    - **輕度扣分 (-1.0分):** 輕微邊界抖動但仍屬同一對齊風格。
    - **重度扣分 (-2.0分):** 出現新的縮排、懸掛縮排，或對齊方式切換（左→中/右）。




##### 策略三：基於統計自適應的主要加分項 (Statistical Adaptive Spacing) 🎯 [v4.3更新]

- **類比:** 智能溫控系統不使用固定的「18°C」，而是根據歷史溫度數據動態計算「過冷」和「過熱」的閾值。
- **規則:** 由於進入經驗規則通道的前提是樣本量不足（< 8個間距），此策略專門應對這種數據稀少的情況。它放棄固定的乘數或像素值，利用統計特徵（平均值與標準差）建立自適應判斷基準，並輸出「合併分數」。
- **重要性:** 🔥 **策略三是唯一的加分項**，承擔主要的合併決策責任。 [v4.3更新]

###### 核心挑戰：樣本量不足的統計難題

在經驗規則通道中，我們面臨的核心挑戰是：**如何在樣本極少的情況下，仍然做出基於統計的合理判斷？**

- **欄位級統計的困境:** 當一個欄位只有3-7個間距時，單憑這幾個數值計算出的平均值和標準差往往不穩定，容易被極端值扭曲。
- **全局級統計的優勢:** 基於整個文檔的統計數據更加穩定可靠，能為小樣本欄位提供一個堅實的判斷基準。

###### 採取方案：全局級統計 (Document-Level Statistics)

- **核心思想:** 當欄位內樣本量不足以支撐可靠的局部統計時，借用整個文檔的「排版DNA」作為判斷基準。
- **計算方式:**
    1.  **首次觸發時**，計算 **整個文檔** 所有行距的 `全局平均值 (global_mean)` 和 `全局標準差 (global_stdDev)` 並緩存。
    2.  使用全局數據定義**統計間距閾值**：
        - `統計分割間距閾值 = global_mean + global_stdDev * 1.0`
        - `統計合併間距閾值 = global_mean - global_stdDev * 1.0` [v4.6更新]

###### ⚠️ 重要術語區分 [v4.3更新]

**請注意：此處的"合併間距閾值"與最終決策的"合併評分閾值"是兩個不同概念！** [v4.3更新]
- `統計合併間距閾值` = 用於判斷行距是否夠小的像素值 (如 5.2px)
- `合併評分閾值` = 最終決策所需的總分數 (固定2.5分，詳見下方)

###### 策略三模糊區間線性遞減評分系統 🎯 [v4.6重大改版]

**設計理念：** 借鑑雙峰統計通道的模糊區間評分機制，建立簡潔優雅的0-5分評分系統。 [v4.6更新]

**核心思想：** [v4.6更新]
- 行距越接近**合併閾值** → 分數越高 (最高5分)
- 行距越接近**分割閾值** → 分數越低 (最低0分)
- 兩者之間形成**模糊區間**，採用線性遞減評分
- **模糊區間中點** (幾何50%位置) 對應的評分值 = (5 + 0) / 2 = **2.5分** = 最終合併閾值

**評分機制：** [v4.6更新]

1. **滿分合併區 (5.0分):**
   - **條件:** `當前行距 ≤ 統計合併間距閾值`
   - **語義:** 行距極小，強烈支持合併
   - **示例:** `spacing = 2.0px ≤ mergeThreshold(4.5px)` → 得分 5.0

2. **模糊區間 (5.0分 → 0分，線性遞減):**
   - **條件:** `統計合併間距閾值 < 當前行距 < 統計分割間距閾值`
   - **計算公式:** 
     ```
     normalized_position = (spacing - mergeThreshold) / (splitThreshold - mergeThreshold)
     score = 5.0 - (normalized_position × 5.0)
     ```
   - **幾何意義:**
     - 接近合併閾值 (位置0%) → 接近5.0分
     - 模糊區間中點 (位置50%) → 正好2.5分 ⭐
     - 接近分割閾值 (位置100%) → 接近0分
   - **示例:** 
     - `spacing = 6.0px` 在模糊區間25%位置 → 得分 3.75
     - `spacing = 9.75px` 在模糊區間50%位置 → 得分 2.5 (閾值線)
     - `spacing = 13.5px` 在模糊區間75%位置 → 得分 1.25

3. **零分分割區 (0分):**
   - **條件:** `當前行距 ≥ 統計分割間距閾值`
   - **語義:** 行距過大，不支持合併
   - **硬性規則:** 此情況通常直接觸發分割，跳過後續評分
   - **示例:** `spacing = 18.0px ≥ splitThreshold(15.0px)` → 得分 0 (或直接分割)

**計算示例：** [v4.6更新]

這個層次清晰的數據結構為後續的翻譯引擎和UI渲染提供了極大的便利。





## 附錄1：技術澄清總結

### 4.4 重要技術澄清總結

**🔍 關鍵概念澄清：**

1. **v4.1 聚類閾值 vs v4.2 合併閾值**
   - **v4.1聚類閾值**：用於步驟3.1的山峰劃分，決定如何將間距值歸類到不同的統計簇中
   - **v4.2合併閾值**：用於步驟3.4的最終決策，決定合併分數需要達到多少才算"及格"

2. **雙峰模型的作用**
   - **不是直接決策工具**：雙峰模型本身不直接決定合併/分割
   - **分數計算基礎**：為步驟3.3提供距離得分計算的統計基礎
   - **區間劃分依據**：將行距劃分為合併區間、分割區間、模糊區間

3. **雙通道架構的核心**
   - **智能路由**：步驟二根據數據質量智能選擇處理通道
   - **功能等價**：步驟三和步驟四都能產生段落分割結果，但適用場景不同
   - **性能互補**：統計通道處理複雜長文本，經驗通道處理簡單短內容

4. **處理流程的邏輯**
   - **線性進行**：步驟一 → 步驟二 是必經路徑
   - **分流處理**：步驟二後分流到步驟三 OR 步驟四（二選一）
   - **結果匯總**：無論走哪個通道，最終都產生相同格式的段落分割結果
