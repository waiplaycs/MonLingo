# MonLingo 核心引擎：高級版面分析規格

**版本:** 6.0
**日期:** 2025年9月6日
**狀態:** 開發中

### 1.0 模組概述

本文件定義了 MonLingo 核心引擎中「高級版面分析 (Advanced Layout Analysis)」模組的演算法規格。

此模組的核心職責是接收來自 OCR 層的、原始且可能零散的文字辨識結果（包含文字內容及其邊界框座標），並將其智能地重組為一個結構化的、符合人類閱讀直覺的版面。最終輸出將清晰地劃分出畫面中的欄位 (Columns) 和段落 (Paragraphs)，為後續的翻譯和使用者介面渲染提供一個乾淨、有序的數據基礎。

本引擎採用三階段處理流程，以確保最高的準確性、穩健性與性能。



---

### 2.0 階段一：高效橫向行合併

此階段旨在高效解決 OCR 引擎可能將單行文字錯誤地分割為多個小框的問題，採用**簡化的相鄰合併策略**，確保邏輯清晰且性能優異。

### 2.1 演算法：相鄰順序合併 (Adjacent Sequential Merging)

1.  **全局預排序 (Global Pre-sorting):**
    - **操作：** 在處理開始時，**立即對所有輸入的文字行進行全局的「從上到下、從左到右」雙重排序** (先按 Y 座標升序，Y 座標相同時再按 X 座標升序)。
    - **目的：** 這是後續所有高效掃描的基礎，確保處理順序符合閱讀直覺，並使演算法行為完全確定。時間複雜度為 `O(n log n)`。

2.  **相鄰合併邏輯 (Adjacent Merging Logic):**
    - **核心策略：** 每個 `line_i` **只與緊鄰的下一個** `line_j` 進行合併判斷，通過兩道關卡的檢驗。
    - **參數策略：** 採用**智能動態閾值系統**，根據當前文檔的特徵自動調整參數，以達到最佳的合併效果。

    - **關卡二 (垂直重疊率):**
        - **條件：** `垂直重疊高度 / min(line_i.Height, line_j.Height) > DynamicVerticalOverlapThreshold`
        - **解釋：** 確保兩個文字框在 Y 軸上的重疊度超過**動態垂直重疊閾值**。此閾值根據文檔整體的行高分布、文字密度等特徵動態計算得出。

    - **關卡三 (相對水平間距):**
        - **條件：** `水平像素間距 < avg(line_i.Height, line_j.Height) * DynamicHorizontalMergeFactor`
        - **解釋：** 確保兩個文字框的水平間距小於其平均高度乘以**動態水平合併因子**。此因子會根據文檔的字體大小變異、排版密度等因素進行調整。

### 2.3 動態參數設計原理

**為什麼選擇動態數值而非固定參數？**

經過深入分析不同文檔類型的處理需求，我們決定採用**智能動態閾值系統**，以下是詳細的優缺點分析：

#### 🎯 動態參數的優勢

**1. 自適應能力強：**
- 能根據不同文檔的字體大小、排版密度自動調整
- 適應各種語言（中文、英文、日文等）的特殊排版需求
- 處理混合語言文檔時更加智能

**2. 準確性更高：**
- 針對特定文檔優化的參數能達到更好的合併效果
- 減少因固定參數導致的誤合併或漏合併
- 能處理極端情況（如超大字體、超小字體）

**3. 魯棒性強：**
- 對不同的OCR引擎輸出具有更好的適應性
- 能處理圖像質量變化對文字識別的影響
- 適應不同解析度和DPI的文檔

**4. 未來擴展性：**
- 可結合機器學習不斷優化參數計算邏輯
- 為不同應用場景提供客製化的參數策略
- 支援用戶偏好和使用習慣的個性化調整

#### ⚠️ 動態參數的挑戰

**1. 實現複雜度較高：**
- 需要實現文檔特徵分析邏輯（平均行高、文字密度、字體大小變異等）
- 參數計算算法本身可能成為性能瓶頸
- 需要更多的測試和驗證工作

**2. 調試難度增加：**
- 算法行為會因文檔而異，問題重現較困難
- 需要建立完善的日誌系統來追蹤參數變化
- 異常情況的診斷和修復更加複雜

**3. 性能考量：**
- 文檔特徵分析需要額外的計算時間
- 可能需要對整個文檔進行預掃描
- 記憶體使用量可能增加

**4. 穩定性風險：**
- 極端情況下可能產生不合理的參數值
- 需要設計合理的參數邊界和異常處理
- 不同版本間的行為一致性需要特別關注

#### 🔧 動態參數計算策略

**文檔特徵分析：**
```pseudocode
function calculate_dynamic_thresholds(input_lines):
    // 1. 計算文檔基礎統計
    avg_height = calculate_average_height(input_lines)
    height_variance = calculate_height_variance(input_lines)
    text_density = calculate_text_density(input_lines)
    
    // 2. 計算動態垂直重疊閾值
    // 基準值0.3，根據高度變異調整
    DynamicVerticalOverlapThreshold = 0.3 - (height_variance * 0.1)
    DynamicVerticalOverlapThreshold = clamp(0.2, 0.5, threshold)
    
    // 3. 計算動態水平合併因子
    // 基準值2.0，根據文字密度調整
    DynamicHorizontalMergeFactor = 2.0 + (text_density * 0.5)
    DynamicHorizontalMergeFactor = clamp(1.5, 3.0, factor)
    
    return (DynamicVerticalOverlapThreshold, DynamicHorizontalMergeFactor)
```

**邊界保護機制：**
- **垂直重疊閾值範圍：** 0.2 ~ 0.5（確保不會過於嚴格或寬鬆）
- **水平合併因子範圍：** 1.5 ~ 3.0（防止極端的間距判斷）
- **異常處理：** 當計算出現異常時，回退到預設值（0.3 和 2.0）

### 2.4 執行流程

**核心執行邏輯：**
```pseudocode
// 第一階段：全局排序和特徵分析
sorted_lines = global_sort(input_lines)  // 全局排序
(DynamicVerticalThreshold, DynamicHorizontalFactor) = calculate_dynamic_thresholds(sorted_lines)

// 第二階段：相鄰合併處理
i = 0
while i < len(sorted_lines):
    current_line = sorted_lines[i]
    
    // 檢查是否還有下一個元素
    if i + 1 >= len(sorted_lines):
        break
        
    next_line = sorted_lines[i + 1]
    
    // 關卡二：垂直重疊率檢查（使用動態閾值）
    if not pass_vertical_overlap_check(current_line, next_line, DynamicVerticalThreshold):
        i += 1  // 失敗，進入下一輪
        continue
        
    // 關卡三：相對水平間距檢查（使用動態因子）
    if not pass_horizontal_spacing_check(current_line, next_line, DynamicHorizontalFactor):
        i += 1  // 失敗，進入下一輪
        continue
        
    // 兩個關卡都通過，執行合併
    merged_line = merge_lines(current_line, next_line)
    sorted_lines[i] = merged_line      // 更新當前位置
    sorted_lines.remove(i + 1)        // 移除已合併的行
    
    // 注意：i 不增加，讓合併後的新line_i繼續與下一個line_j合併
```

**動態參數計算詳細流程：**
```pseudocode
function calculate_dynamic_thresholds(sorted_lines):
    // 1. 文檔基礎統計
    heights = [line.height for line in sorted_lines]
    avg_height = mean(heights)
    height_std = standard_deviation(heights)
    height_variance = height_std / avg_height  // 正規化變異係數
    
    // 2. 文字密度分析
    total_text_area = sum([line.width * line.height for line in sorted_lines])
    document_area = calculate_document_bounding_box_area(sorted_lines)
    text_density = total_text_area / document_area
    
    // 3. 動態閾值計算
    // 垂直重疊閾值：基礎0.3，高度變異大時放寬，小時收緊
    vertical_threshold = 0.3 - (height_variance - 0.2) * 0.5
    vertical_threshold = clamp(0.2, 0.5, vertical_threshold)
    
    // 水平合併因子：基礎2.0，密度高時收緊，低時放寬
    horizontal_factor = 2.0 + (0.5 - text_density) * 2.0
    horizontal_factor = clamp(1.5, 3.0, horizontal_factor)
    
    return (vertical_threshold, horizontal_factor)
```

### 2.5 合併策略特點

**1. 相鄰檢查：**
- 每個 `line_i` 只檢查緊鄰的 `line_j`（下一個元素）
- 無需複雜的掃描窗口或截斷邏輯

**2. 立即終止：**
- 任一關卡失敗立即進入下一輪 `line_i`
- 不會浪費時間檢查其他候選

**3. 連續合併：**
- 合併成功後，新的 `line_i` 立即與下一個元素繼續嘗試合併
- 支持多個片段的連續合併（如："Hello" + " " + "World" → "Hello World"）

**4. 簡化邏輯：**
- 移除了複雜的截斷條件和多重掃描
- 邏輯清晰，易於實現和調試

### 2.6 預期效果

- **邏輯簡化：** 去除複雜的動態掃描窗口和截斷機制，採用直觀的相鄰合併策略
- **智能自適應：** 使用動態閾值系統，能根據文檔特徵自動調整參數，提升合併準確性
- **魯棒性強：** 能適應不同字體、語言、排版密度的文檔，處理各種極端情況
- **性能平衡：** 在保持良好性能的同時（O(n)到O(n²)），提供更高的處理準確性
- **連續合併：** 支持多個連續片段的自動合併，如 "單" + "詞" + "合併" → "單詞合併"
- **工程可控：** 通過邊界保護機制確保參數在合理範圍內，避免極端值的影響
- **可擴展性：** 動態參數系統為未來的算法優化和客製化提供了基礎架構

### 2.7 實際應用場景

**典型合併場景：**
```
輸入：["你", "好", "世", "界"]  (4個相鄰的字符框)
處理過程：
1. "你" + "好" → "你好" (通過兩個關卡)
2. "你好" + "世" → "你好世" (通過兩個關卡)  
3. "你好世" + "界" → "你好世界" (通過兩個關卡)
輸出：["你好世界"]
```

**跨欄位場景：**
```
輸入：["標題A", "內容1", "標題B"] (不同Y位置的框)
處理過程：
1. "標題A" + "內容1" → 關卡二失敗 (Y軸重疊度不足)
2. "內容1" + "標題B" → 關卡二失敗 (Y軸重疊度不足)
輸出：["標題A", "內容1", "標題B"] (保持原狀)
```
