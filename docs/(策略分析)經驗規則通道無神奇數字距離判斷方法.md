# 經驗規則通道無神奇數字距離判斷方法

**文檔版本:** 1.0  
**創建日期:** 2025年9月17日  
**相關版本:** MonLingo v3.5+  

## 📋 文檔概述

本文檔詳細分析在雙通道架構中，經驗規則通道如何避免依賴固定的「神奇數字」來進行距離判斷。透過類比和實際案例，說明五種主要策略的工作原理和適用場景。

---

## 🤔 引言：何時需要經驗規則通道？

當雙峰統計模型因為數據不足或模式模糊而失效時，經驗規則通道將被激活。這通常發生在以下幾種特徵的欄位中：

1.  **結構高度一致的內容 (Highly Structured & Uniform Content):**
    - **特徵:** 行間距高度統一，只有一個統計峰值。
    - **案例:** 列表、UI選單、代碼塊、表格。

2.  **內容極簡的欄位 (Minimalist Content Columns):**
    - **特徵:** 行數太少（< 4行），無法提供足夠的統計樣本。
    - **案例:** 標題、圖片說明、簡短提示。

3.  **間距模式模糊的內容 (Ambiguous Spacing Patterns):**
    - **特徵:** 段內和段間距非常接近，無法清晰分離出兩個峰值。
    - **案例:** 高密度排版（如法律文件）、格式混亂的文本。

接下來的策略將展示如何針對這些「疑難雜症」進行有效處理。

## 🎯 策略二：統計自適應法 (Statistical Adaptive Method)

### 概念類比：「智能溫控系統」

想像你是一個智能溫控系統的設計師。傳統的溫控器使用固定設定（比如「低於18°C開暖氣，高於25°C開冷氣」），但你想設計一個更聰明的系統。

**傳統固定閾值方法：**
```
if (temperature < 18) turnOnHeater();
if (temperature > 25) turnOnAirCon();
```

**統計自適應方法：**
```javascript
// 收集過去一週的溫度數據
const weeklyTemps = [16, 18, 22, 24, 19, 21, 23, 20, 17, 25, 22];
const stats = calculateStatistics(weeklyTemps);
// 平均溫度：20.6°C，標準差：3.1°C

// 動態計算舒適區間
const comfortZone = {
    tooCold: stats.mean - stats.standardDeviation,     // 17.5°C
    tooHot: stats.mean + stats.standardDeviation       // 23.7°C
};

// 自適應控制
if (currentTemp < comfortZone.tooCold) turnOnHeater();
if (currentTemp > comfortZone.tooHot) turnOnAirCon();
```

### 在版面分析中的應用

**應對挑戰：**
- **結構高度一致的內容：** 當所有間距都差不多時（單一峰值），統計標準差會很小。這會讓 `mergeThreshold` 和 `splitThreshold` 非常接近，雖然無法有效分割，但它準確地反映了「這是一個整體」的數據現實，避免了使用任意大數值進行錯誤分割。
- **間距模式模糊的內容：** 當段內和段間距混雜時，雖然平均值和標準差可能不完美，但它們提供了一個基於當前文檔數據的「重心」，比任何固定的神奇數字都更具參考價值。

**場景：** 判斷兩行文字之間的間距是「段落內」還是「段落間」

```javascript
function calculateAdaptiveThresholds(documentSpacings) {
    // 收集文檔中所有行間距數據
    const spacings = [2, 3, 2, 15, 3, 2, 18, 2, 4, 16, 3];
    
    // 統計分析
    const stats = {
        mean: 8.18,           // 平均間距
        standardDeviation: 6.92,  // 標準差
        median: 3.0,          // 中位數
        q1: 2.5, q3: 16.0     // 四分位數
    };
    
    // 自適應閾值計算
    return {
        // 小間距（段落內）：平均值 - 0.5個標準差
        mergeThreshold: stats.mean - stats.standardDeviation * 0.5,  // 4.72px
        
        // 大間距（段落間）：平均值 + 0.8個標準差  
        splitThreshold: stats.mean + stats.standardDeviation * 0.8,  // 13.72px
        
        // 穩健估計（基於四分位數，不受極值影響）
        robustThreshold: stats.q1 + (stats.q3 - stats.q1) * 0.3     // 6.55px
    };
}
```

**優勢：**
- 🎯 **文檔自適應**：根據每個文檔的實際特徵調整
- 📊 **統計穩健**：不容易被個別異常值影響
- 🔄 **動態更新**：隨著更多數據而改善

## 🌊 策略四：漸進式評分法 (Progressive Scoring Method)

### 概念類比：「汽車油門控制」

傳統的開關式思維就像老式電燈開關：要麼全開，要麼全關。而漸進式評分法就像現代汽車的油門踏板。

**傳統硬切割方法：**
```
間距 < 5px  → 合併 (分數=1.0)
間距 ≥ 5px  → 分割 (分數=0.0)
```
這就像一個粗暴的電燈開關：一跨過5px這條線，就從「完全合併」突然跳到「完全分割」。

**漸進式評分方法：**
```javascript
function calculateProgressiveScore(spacing, idealSpacing) {
    // Sigmoid函數：提供平滑的過渡
    function sigmoidTransition(value, center, steepness) {
        return 1 / (1 + Math.exp(-steepness * (value - center)));
    }
    
    // 理想間距為 3px，漸進過渡
    const score = sigmoidTransition(spacing, idealSpacing, 0.5);
    
    /*
    spacing = 1px  → score = 0.88 (很可能合併)
    spacing = 3px  → score = 0.50 (模糊地帶)  
    spacing = 5px  → score = 0.12 (很可能分割)
    spacing = 7px  → score = 0.02 (幾乎確定分割)
    */
    
    return score;
}
```

### 在版面分析中的應用

**應對挑戰：**
- **間距模式模糊的內容：** 這是此策略最擅長的場景。當段內和段間距非常接近時，任何固定的「切割點」都必然會出錯。漸進式評分法則提供了一個從「極可能合併」到「極可能分割」的平滑過渡，允許系統在模糊地帶做出更細膩的、基於可能性的判斷，而不是武斷的二元選擇。

### 實際應用案例

**場景：** 處理學術論文的段落識別

```javascript
function analyzePaperLayout(lines) {
    const results = [];
    
    for (let i = 1; i < lines.length; i++) {
        const spacing = lines[i].top - lines[i-1].bottom;
        
        // 多維度漸進評分
        const scores = {
            // 距離評分：使用平滑曲線
            distance: calculateDistanceScore(spacing, 4.0),  // 理想段落內間距4px
            
            // 縮排評分：檢查是否有段落縮排
            indentation: calculateIndentationScore(lines[i].left, lines[i-1].left),
            
            // 對齊評分：檢查左對齊一致性
            alignment: calculateAlignmentScore(lines[i], lines[i-1])
        };
        
        // 加權合併（避免硬切割）
        const finalScore = 
            scores.distance * 0.5 +      // 距離權重50%
            scores.indentation * 0.3 +   // 縮排權重30%  
            scores.alignment * 0.2;      // 對齊權重20%
        
        results.push({
            lineIndex: i,
            mergeScore: finalScore,
            decision: finalScore > 0.6 ? 'merge' : 'split'
        });
    }
    
    return results;
}
```

**優勢：**
- 🌊 **平滑過渡**：避免硬切割帶來的邊界效應
- 🎚️ **精細控制**：可以表達「可能性」而非「絕對」
- 🔧 **易於調整**：改變曲線參數即可微調行為

## 🎭 策略五：多維度綜合法 (Multi-Dimensional Integration)

### 概念類比：「相親決策系統」

想像你要設計一個相親匹配系統。傳統方法可能只看一個條件：

**單一維度方法：**
```
if (age_difference < 3) return "匹配";
else return "不匹配";
```

但現實中，相親匹配需要考慮多個因素：

**多維度綜合方法：**
```javascript
function calculateMatchScore(person1, person2, context) {
    const factors = {
        // 年齡匹配度（標準化到0-1）
        age: calculateAgeCompatibility(person1.age, person2.age),
        
        // 興趣相似度
        interests: calculateInterestOverlap(person1.hobbies, person2.hobbies),
        
        // 教育背景匹配
        education: calculateEducationMatch(person1.education, person2.education),
        
        // 地理位置便利性
        location: calculateLocationScore(person1.city, person2.city),
        
        // 朋友推薦信心度
        recommendation: context.recommenderConfidence
    };
    
    // 動態權重（根據用戶偏好調整）
    const weights = calculatePersonalizedWeights(person1.preferences);
    
    // 加權平均
    const totalScore = 
        factors.age * weights.age +
        factors.interests * weights.interests +
        factors.education * weights.education +
        factors.location * weights.location +
        factors.recommendation * weights.recommendation;
    
    return {
        score: totalScore,
        confidence: calculateConfidence(factors, weights),
        breakdown: factors  // 可解釋性
    };
}
```

### 在版面分析中的應用

**應對挑戰：**
- **內容極簡的欄位：** 當行數少於4行，無法進行有效的統計分析時，此策略的優勢盡顯。它不依賴大量的統計樣本，而是通過綜合分析僅有幾行中的多種特徵（如字體、對齊、縮排、與周圍元素的關係）來做出穩健的判斷。例如，一個兩行的標題，可以通過「字體更大」、「居中對齊」、「與下方正文間距較大」等多個維度確認其獨立性。
- **所有疑難雜症：** 這是最通用的策略，能夠為所有三種疑難情況提供全面的分析框架。

**場景：** 複雜版面的段落分割決策

```javascript
function calculateMultiDimensionalMergeScore(lineA, lineB, documentContext) {
    const features = {
        // 1. 距離特徵（標準化）
        distance: normalizeDistanceScore(
            Math.abs(lineA.spacing - lineB.spacing),
            documentContext.spacingStatistics
        ),
        
        // 2. 字體一致性
        fontConsistency: calculateFontSimilarity(lineA.font, lineB.font),
        
        // 3. 對齊模式
        alignmentPattern: calculateAlignmentConsistency(lineA, lineB),
        
        // 4. 語義連續性（基於內容）
        semanticContinuity: analyzeSentenceContinuity(lineA.text, lineB.text),
        
        // 5. 上下文適配度
        contextualFit: calculateContextualConsistency(lineA, lineB, documentContext),
        
        // 6. 數據可信度
        dataConfidence: calculateDataReliability(documentContext.sampleSize)
    };
    
    // 動態權重分配（基於數據質量和文檔類型）
    const weights = calculateAdaptiveWeights(documentContext.documentType, features.dataConfidence);
    
    // 加權綜合評分
    const finalScore = linearCombination(features, weights);
    
    return {
        score: finalScore,
        confidence: weights.confidence,
        reasoning: {
            dominantFactor: findDominantFactor(features, weights),
            uncertaintyAreas: identifyUncertainties(features),
            recommendations: generateRecommendations(features, weights)
        }
    };
}
```

**實際案例：新聞文章分析**

- 🎯 **全面考量**：避免單一指標的局限性

## 🎛️ 策略六：模式識別法 (Pattern Recognition Method)

### 概念類比：「醫生診斷系統」

經驗豐富的醫生不會僅憑一個症狀就下診斷，而是首先識別病患屬於哪種「症候群模式」，然後採用相應的診斷策略。

**醫療診斷類比：**
```javascript
function diagnosePatient(symptoms, patientHistory) {
    // 第一步：模式識別
    const clinicalPattern = identifyMedicalPattern(symptoms);
    
    switch(clinicalPattern.type) {
        case "ACUTE_INFECTION":
            return useInfectionProtocol(symptoms, patientHistory);
            
        case "CHRONIC_CONDITION":
            return useChronicCareProtocol(symptoms, patientHistory);
            
        case "EMERGENCY_CASE":
            return useEmergencyProtocol(symptoms, patientHistory);
            
        default:
            return useGeneralScreeningProtocol(symptoms, patientHistory);
    }
}
```

### 在版面分析中的應用

**應對挑戰：**
- **結構高度一致的內容：** 這是此策略的核心優勢。它可以被訓練來識別特定的、高度結構化的模式，如「代碼塊」、「項目列表」、「表格行」或「UI菜單」。一旦識別出這些模式，系統就可以應用專門為該模式設計的規則（例如，「在代碼塊內部，除非是空行，否則全部合併」），而不是依賴通用的間距分析，從而極大地提高準確性。

**文檔類型模式識別：**

## 🌈 混合策略 (Hybrid Strategy)

### 概念類比：「智能投資顧問」

最優秀的投資顧問不會只用一種分析方法，而是結合多種策略：

```javascript
function makeInvestmentDecision(stock, market, investor) {
    // 第一步：識別市場狀態
    const marketPattern = identifyMarketCondition(market);
    
    // 第二步：根據市場狀態選擇主要策略
    let primaryStrategy, fallbackStrategies;
    
    switch(marketPattern.type) {
        case "BULL_MARKET":
            primaryStrategy = "technicalAnalysis";
            fallbackStrategies = ["fundamentalAnalysis", "sentimentAnalysis"];
            break;
            
        case "BEAR_MARKET":
            primaryStrategy = "fundamentalAnalysis";
            fallbackStrategies = ["riskAnalysis", "diversificationAnalysis"];
            break;
            
        case "VOLATILE_MARKET":
            primaryStrategy = "riskAnalysis";
            fallbackStrategies = ["technicalAnalysis", "adaptiveStrategy"];
            break;
    }
    
    // 第三步：執行主要策略，必要時切換到備選策略
    let decision = applyStrategy(primaryStrategy, stock, market, investor);
    
    if (decision.confidence < 0.7) {
        // 信心不足時，嘗試備選策略
        for (const fallback of fallbackStrategies) {
            const fallbackDecision = applyStrategy(fallback, stock, market, investor);
            if (fallbackDecision.confidence > decision.confidence) {
                decision = fallbackDecision;
                break;
            }
        }
    }
    
    return decision;
}
```

### 在版面分析中的混合策略

**應對挑戰：**
- **應對所有疑難雜症的元策略：** 混合策略本身就是為了應對複雜性和不確定性而設計的。它首先會嘗試識别當前內容屬於哪種疑難雜症（例如，通過檢查行數判斷是否為「內容極簡」，通過模式識別判斷是否為「結構高度一致」），然後動態地選擇最適合的子策略（如為「內容極簡」場景優先啟用多維度分析），從而實現對所有情況的智能、自適應處理。

**v3.6 改進方案：自適應混合決策系統**

```javascript
function calculateHybridMergeScore(lineA, lineB, documentContext) {
    // 第一階段：文檔模式識別
    const layoutPattern = recognizeDocumentLayoutPattern(documentContext);
    
    // 第二階段：數據質量評估
    const dataQuality = assessDataQuality(documentContext);
    
    // 第三階段：策略選擇與組合
    let primaryResult, strategyChain;
    
    if (layoutPattern.confidence > 0.8 && dataQuality.sufficient) {
        // 高信心情況：使用模式特定策略
        primaryResult = applyPatternSpecificStrategy(lineA, lineB, layoutPattern);
        strategyChain = ["pattern-specific", "multi-dimensional", "statistical"];
        
    } else if (dataQuality.sufficient) {
        // 中等信心：使用統計自適應策略
        primaryResult = applyStatisticalAdaptiveStrategy(lineA, lineB, documentContext);
        strategyChain = ["statistical", "progressive", "pattern-fallback"];
        
    } else {
        // 低信心：使用保守的多維度策略
        primaryResult = applyMultiDimensionalStrategy(lineA, lineB, documentContext);
        strategyChain = ["multi-dimensional", "progressive", "basic-rules"];
    }
    
    // 第四階段：信心度檢查與策略切換
    if (primaryResult.confidence < 0.6) {
        // 主策略信心不足，嘗試備選策略
        primaryResult = executeStrategyChain(strategyChain, lineA, lineB, documentContext);
    }
    
    // 第五階段：最終決策與解釋
    return {
        decision: primaryResult.score > primaryResult.threshold ? "merge" : "split",
        score: primaryResult.score,
        confidence: primaryResult.confidence,
        strategy: primaryResult.usedStrategy,
        reasoning: generateExplanation(primaryResult, strategyChain),
        metadata: {
            documentPattern: layoutPattern,
            dataQuality: dataQuality,
            alternativeScores: primaryResult.alternatives
        }
    };
}
```

**策略切換邏輯：**

```javascript
function executeStrategyChain(strategies, lineA, lineB, context) {
    let bestResult = { score: 0, confidence: 0 };
    
    for (const strategyName of strategies) {
        let result;
        
        switch(strategyName) {
            case "pattern-specific":
                result = applyPatternSpecificStrategy(lineA, lineB, context.pattern);
                break;
                
            case "statistical":
                result = applyStatisticalAdaptiveStrategy(lineA, lineB, context);
                break;
                
            case "multi-dimensional":
                result = applyMultiDimensionalStrategy(lineA, lineB, context);
                break;
                
            case "progressive":
                result = applyProgressiveScoringStrategy(lineA, lineB, context);
                break;
                
            case "basic-rules":
                result = applyBasicRulesStrategy(lineA, lineB, context);
                break;
        }
        
        // 選擇信心度最高的結果
        if (result.confidence > bestResult.confidence) {
            bestResult = result;
            bestResult.usedStrategy = strategyName;
        }
        
        // 如果信心度足夠高，提前退出
        if (result.confidence > 0.8) {
            break;
        }
    }
    
    return bestResult;
}
```
