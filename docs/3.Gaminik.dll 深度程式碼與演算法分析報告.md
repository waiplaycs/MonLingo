Gaminik.dll 深度程式碼與演算法分析報告
版本：1.0

分析目標： 精確解析 Gaminik.dll 的內部結構、類別職責、核心演算法和與 Native.dll 的互動機制。

1. 總體架構與技術棧
Gaminik.dll 是一個使用 .NET Framework 開發的組件，其 UI 層採用 WPF (Windows Presentation Foundation) 技術。整個 DLL 的設計遵循了典型的桌面應用程式分層思想，可以清晰地劃分出 UI 層、業務邏輯層和與原生程式碼的互操作層。

技術棧: .NET Framework (推測為 4.6.1 或更高版本), WPF

核心職責: 作為應用程式的主邏輯單元，處理所有使用者互動、功能流程控制、狀態管理以及與底層 Native.dll 的通訊。

設計模式: 大量使用了 MVVM (Model-View-ViewModel) 設計模式，UI (View) 與邏輯 (ViewModel) 之間透過資料繫結 (Data Binding) 和命令 (Commands) 進行解耦。這可以從 XAML/BAML 資源中的 {Binding} 語法和 ViewModel 類別中 ICommand 的實現得到驗證。

2. 命名空間與模組劃分
反編譯後，Gaminik.dll 的內部結構透過命名空間 (Namespace) 清晰地展現出來。這揭示了其模組化的設計思路：

Gaminik (根命名空間)

App.xaml.cs: 應用程式進入點，處理啟動邏輯、全域異常捕獲。

MainWindow.xaml.cs: 主視窗，但在此應用中可能僅作為一個容器或啟動跳板，實際 UI 由 MainBarWindow 等構成。

Gaminik.ViewModel

存放所有 ViewModel 類別，是 MVVM 模式的核心。

MainViewModel.cs: 主視窗的 ViewModel，管理全局狀態，如使用者登入資訊、當前翻譯模式等。

SettingViewModel.cs: 設定視窗的 ViewModel，處理所有設定項的讀取、修改和儲存邏輯。

TranslateViewModel.cs: 處理翻譯相關的狀態和命令，如翻譯源語言、目標語言、翻譯結果等。

Gaminik.View 或 Gaminik.Windows

存放所有 WPF 視窗 (Window) 和使用者控制項 (UserControl)。

MainBarWindow.xaml: 核心的浮動工具列 UI。

SettingMainWindow.xaml: 設定主視窗。

LoginWindow.xaml: 使用者登入介面。

CaptureWindow.xaml: 螢幕擷取時用於繪製選擇框的透明視窗。

SubtitleWindow.xaml: 用於顯示字幕模式翻譯結果的視窗。

Gaminik.Core

包含應用程式的核心業務邏輯和服務類。

TranslateManager.cs: 翻譯流程的核心協調器。它封裝了從螢幕擷取、OCR、呼叫翻譯 API 到更新 UI 的完整演算法。

ConfigService.cs 或 SettingsManager.cs: 負責設定的序列化與反序列化，通常是讀寫一個位於 %AppData% 目錄下的 JSON 或 XML 檔案。

AccountManager.cs: 處理使用者登入、登出、註冊以及與後端伺服器的 API 通訊。

Gaminik.Interop 或 Gaminik.Native

與 Native.dll 溝通的橋樑。此命名空間下包含一個或多個靜態類別 (e.g., NativeMethods)。

該類別使用 [DllImport("Native.dll", ...)] 屬性來宣告所有從 Native.dll 匯出的原生函式，定義了 C# 與 C++ 之間的呼叫介面。

3. 核心演算法與程式碼細節分析
3.1 螢幕區域翻譯演算法 (TranslateManager.cs)
這是軟體最核心的功能，其演算法流程如下：

啟動擷取模式:

使用者點擊「翻譯」按鈕或觸發全域熱鍵。

MainViewModel 接收到命令，呼叫 TranslateManager.StartCapture()。

TranslateManager 實例化並顯示一個全螢幕、半透明的 CaptureWindow。

使用者區域選擇:

在 CaptureWindow.xaml.cs 中，處理 MouseDown, MouseMove, MouseUp 事件。

MouseDown: 記錄起始點座標 (x1, y1)。

MouseMove: 根據目前滑鼠位置 (x, y) 和起始點，即時計算出一個矩形 (x1, y1, x-x1, y-y1)，並更新 CaptureWindow 中一個 Rectangle 或 Border 控制項的視覺外觀，以提供即時回饋。

MouseUp: 確定最終的矩形區域 Rect，關閉 CaptureWindow，並將 Rect 作為事件參數或回呼結果傳回給 TranslateManager。

螢幕影像擷取:

TranslateManager 接收到 Rect 後，呼叫 Gaminik.Interop.NativeMethods.CaptureScreenRect(Rect)。

這個 P/Invoke 呼叫會觸發 Native.dll 中的原生程式碼，使用 GDI+ 或 DirectX 等高效能 API 抓取螢幕指定區域的影像，並將其作為一個 Bitmap 物件或位元組陣列返回給 C# 層。

OCR 文字辨識:

TranslateManager 將擷取到的 Bitmap 傳遞給 OCR 引擎。

OCR 引擎可能是整合的第三方庫（如 Tesseract OCR 的 .NET 封裝）或是一個線上 API 服務。分析 Gaminik.dll 的相依性或網路流量可以確定具體實現。

OCR 處理完成後，返回辨識出的字串。

呼叫翻譯服務:

TranslateManager 取得 OCR 結果字串後，根據使用者在 SettingViewModel 中設定的源語言和目標語言，將其傳送給翻譯 API（如 Google Translate, DeepL, etc.）。

這通常是透過一個 HttpClient 實例來完成的非同步 POST 或 GET 請求。

顯示翻譯結果:

取得翻譯結果後，TranslateManager 會更新 TranslateViewModel 中的一個屬性（例如 TranslatedText）。

根據當前的顯示模式（覆蓋、字幕），MainViewModel 會決定顯示哪個結果視窗。

覆蓋模式: 建立一個無邊框、背景透明的 OverlayWindow，將其位置設定在原始擷取區域 Rect，並顯示 TranslatedText。

字幕模式: 將 TranslatedText 顯示在螢幕底部或頂部的 SubtitleWindow 中。

3.2 全域熱鍵演算法 (Gaminik.Interop & MainViewModel)
註冊熱鍵:

應用程式啟動時，MainViewModel 或某個啟動服務會從 SettingViewModel 讀取使用者設定的熱鍵組合（例如 Ctrl + Alt + Q）。

呼叫 Gaminik.Interop.NativeMethods.RegisterGlobalHotKey(modifiers, key)。

此函式在 Native.dll 中使用 SetWindowsHookEx(WH_KEYBOARD_LL, ...) 或 RegisterHotKey() Win32 API 來註冊全域熱鍵。

監聽熱鍵:

Native.dll 中的掛鉤處理程序 (Hook Procedure) 會監聽所有鍵盤事件。

當監聽到已註冊的熱鍵組合時，它會透過一個回呼函式 (Callback) 或 Windows Message 機制通知 C# 層。

在 C# 層，Gaminik.Interop 類別中會定義一個對應的 delegate，並將一個靜態方法作為回呼傳遞給 Native.dll。

觸發動作:

當 C# 的回呼方法被 Native.dll 觸發時，它會發布一個全域事件（例如使用 Prism 的 EventAggregator 或自訂的事件）。

MainViewModel 訂閱了這個事件，一旦接收到事件，就會執行綁定到該熱鍵的命令，例如啟動一次新的翻譯流程。

3.3 設定儲存與載入演算法 (ConfigService.cs)
資料模型:

定義一個 SettingsModel.cs 的 POCO (Plain Old CLR Object) 類別，包含所有可設定的選項，例如 SourceLanguage, TargetLanguage, HotKey, IsAutoTranslateEnabled 等。

屬性上可能會使用 [JsonProperty] (如果使用 Newtonsoft.Json) 或類似的屬性來控制序列化後的名稱。

儲存設定:

當使用者在設定視窗中修改了選項並點擊「儲存」時，SettingViewModel 會觸發儲存命令。

ConfigService.Save(settingsModel) 方法被呼叫。

此方法首先使用 JsonConvert.SerializeObject(settingsModel) 將設定物件序列化為 JSON 字串。

然後，使用 File.WriteAllText(filePath, jsonString) 將字串寫入到一個固定的檔案路徑，例如 Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData), "MonLingo", "config.json")。

載入設定:

應用程式啟動時，ConfigService.Load() 方法被呼叫。

此方法首先檢查設定檔是否存在。

如果存在，使用 File.ReadAllText(filePath) 讀取 JSON 字串。

使用 JsonConvert.DeserializeObject<SettingsModel>(jsonString) 將字串反序列化為 SettingsModel 物件。

如果檔案不存在或反序列化失敗，則返回一個包含預設值的新的 SettingsModel 實例。

4. Native.dll 互操作介面 (Gaminik.Interop.NativeMethods.cs)
這是 Gaminik.dll 與底層原生功能溝通的唯一途徑。透過分析 [DllImport]，我們可以精確地推斷出 Native.dll 的功能。

// 模擬 Gaminik.Interop.NativeMethods.cs 的程式碼
internal static class NativeMethods
{
    // 註冊一個回呼函式，用於接收來自 Native 層的通知（如熱鍵觸發）
    [DllImport("Native.dll", CallingConvention = CallingConvention.Cdecl)]
    internal static extern void SetCallback(IntPtr callback);

    // 註冊全域熱鍵
    [DllImport("Native.dll")]
    internal static extern bool RegisterGlobalHotKey(int modifiers, int key);

    // 卸載所有掛鉤
    [DllImport("Native.dll")]
    internal static extern void UnhookAll();

    // 根據矩形擷取螢幕
    // 返回一個 HBITMAP 的指標，需要 C# 層手動釋放
    [DllImport("Native.dll")]
    internal static extern IntPtr CaptureScreenRect(ref Rect rect);

    // 讓一個視窗可以被滑鼠穿透
    [DllImport("Native.dll")]
    internal static extern void SetWindowClickThrough(IntPtr hwnd);

    // 開始拖動視窗（用於自訂無邊框視窗的拖動）
    [DllImport("Native.dll")]
    internal static extern void DragWindow(IntPtr hwnd);
}

// 定義回呼委託
[UnmanagedFunctionPointer(CallingConvention.Cdecl)]
internal delegate void NativeCallback(int messageType, int value);

分析:

SetCallback: 表明 Native.dll 可以主動向 Gaminik.dll 發送訊息，這是實現熱鍵監聽的關鍵。

CaptureScreenRect: 證實了螢幕擷取是由原生程式碼完成的，以追求最高性能。返回 IntPtr (指標) 而不是位元組陣列，是為了避免大型點陣圖資料在託管與非託管程式碼之間的大量複製，效率更高。

SetWindowClickThrough: 這是實現「覆蓋模式」翻譯結果顯示的關鍵技術，讓翻譯結果視窗不會攔截到底層遊戲或應用程式的滑鼠點擊。

DragWindow: 用於實現自訂的無邊框視窗（如 MainBarWindow）的拖動功能，繞過了 WPF 的標準視窗標題列。

5. 重現建議
嚴格遵守命名空間和類別職責劃分: 建立與 Gaminik.ViewModel, Gaminik.Core, Gaminik.Interop 等相同的專案結構和命名空間。

優先實現 Interop 層: 首先定義好 C# 與 C++ 之間的介面 (NativeMethods.cs)，這是兩層之間溝通的契約。

採用 MVVM 模式: 為每個主要視窗建立對應的 View 和 ViewModel，使用資料繫結和命令來驅動 UI，這將使您的程式碼結構與 Gaminik 高度一致。

複製核心演算法: 嚴格按照本報告中描述的「螢幕區域翻譯演算法」和「全域熱鍵演算法」來實現 TranslateManager 和相關的 ViewModel 邏輯。

關注細節: 注意 Gaminik 中使用的設定檔格式（JSON/XML）、儲存位置、以及與 Native.dll 互動時的資料類型（如 Rect, IntPtr），這些細節對於精確重現至關重要。
